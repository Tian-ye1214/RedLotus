# RedLotus 开发约定

本文规定开发偏好、修改边界及验收条件。组件行为以[项目设计](design.md)为依据，入口和数据归属见[项目总览](README.md)。

## 修改边界

- **禁止添加过度引导、裁剪、硬编码运行参数和隐藏默认值。** 每项修改对应明确需求，不自行增加配置、数量限制、依赖、框架或替代配置文件。
- 功能完整、正确和可读是前提。优先复用已有函数、合适的继承、标准库及第三方库原生能力，删除重复状态和无职责包装，不为假设问题增加扩展层或兜底分支。
- 保留用户已有工作区修改、删除和恢复的内容，不整体回滚，不借修复覆盖提示词或私人配置。重构保留可观察行为及副作用，不靠删功能、测试或断言达标。
- 已授权且必要的工作持续完成，不重复索取同一确认。实际设计分歧须说明差异、用途和影响；未获授权的功能扩展不并入修复。
- 修复先定位原因、保留首次失败，再做最小修改和原场景重测。结论不能超出证据范围，未知结果不能写成成功。
- 设计要求与实际实现的差异在任务交付中如实说明，不能把错误实现改写成新需求，也不能把待办或进度追加进设计稿。

## 配置与凭据

[三层逐字段读取规则](design.md#配置读取与编辑)是固定约定，未经用户明确要求不得改变来源、顺序或字段的合法空值语义。

参数范围以现有项目 `config.json` 为依据，保留 BFL 接入及其连接字段的明确例外。不新增模型预设、命名网关、分层覆盖、额外别名、通用 schema 或运行参数填表。模型、采样、输出、RAG、路径及保留策略由既有入口读取，不搬入代码或隐藏模板。删除应用额外策略后使用库原生行为，不把库默认值抄成常量；显式业务入参仍须传递。

- 现有项目 `config.json`、项目 `.env` 和全局配置保持不变；只有用户明确授权的字段差异可以修改。修改前后核对字节及差异，不自动清洗无效旧字段或回写所有来源的合并结果。
- 禁止复制、备份、迁移、分发、上传或输出现有私人配置；禁止把配置、凭据和个人记忆放入模型输入、日志、夹具或被测 Agent 可读取的测试资料。
- 凭据仅用于相应服务认证。测试配置在明确的隔离临时目录人工构造，不从私人配置复制；只核对真实配置哈希，不输出私人字段清单或合并内容。
- 首次引导仅处理已有角色的模型选择与连接，不恢复非模型参数的启动依赖或缺项补填提示。模型及连接编辑继续保留凭据隐藏、Esc 取消不保存、文件锁和原子差异提交。
- 新增模型服务、外发材料、依赖环境或账号操作须在实际授权范围内。明确目标解释器、安装位置和影响，不修改无关全局依赖。

## 提示词与工具

- 应用维护的提示词使用英文并保留完整任务约束，放在提示词资源文件中；用户原文、引用和界面文案不强制翻译。未经允许不改写用户维护或恢复的正文，不把提示词放进配置或在 Python 中隐藏补写。
- 会话提示词快照、工具身份和上下文规则遵守[项目设计](design.md#提示词与压缩)。不通过重写 system、缩减输出配置、缩小证据窗口或截断原文获得压缩或缓存成绩。
- Agent 创建位置明确选择工具集合。英文函数 docstring 是唯一工具描述来源，签名、类型、返回值和实际行为一致，不通过外部 Markdown 改写描述或决定权限。
- Skills 渐进读取，执行经过共享检查入口；业务实现不能藏入 Skills 资源。保留工具层路径、进程、身份和审查边界，不引入系统 Hook、权限库或 IDE 插件绕过这些边界。
- 参数错误原样报告，不自动改写模型工具参数或事后修正产物。记忆改动聚焦正确写入和现有恢复流程，不自行新增历史修复、维护命令或备份框架。

## 代码组织与精简

**代码简洁性是实现偏好，功能完整、正确和可读是前提。** 不以大函数、挤行、隐藏实现或删功能换取规模数字。

| 对象 | 硬性条件 |
| --- | --- |
| 应用模块 | 总数最多 8 个，职责对应[八模块边界](design.md#架构与组件职责) |
| 模块文件 | 每模块递归最多 5 个 Python 文件，包含 `__init__.py` |
| 单文件规模 | 最多 500 有效代码行 |
| 应用净精简 | 应用有效代码总量少于 10,373 行；代码差异的删除行数大于新增行数 |
| 自有测试 | 每组最多 5 个 Python 文件，每文件最多 500 有效代码行 |

有效行按 Python 逻辑语句换行统计，函数、类和装饰器计入；空行、注释及说明文档字符串不计，多行参数和续行合计一行。物理行数不设上限，只用于可读性与增删审查。净精简统计不能靠删除说明或测试凑数。

第三方 Skills 资源不计入自有业务文件；自有工具、Skills 管理器及业务实现必须计入。测试和打包脚本单独核对，不能承载外移的应用实现。不得通过分号堆叠、嵌套目录、重复拆组、动态执行字符串或把业务代码放入资源规避限制。

新增或调整模块须说明唯一职责、必要性、替代与复用方案和依赖收益，不突破总数上限。每个函数的审查覆盖职责、调用方或注册入口、可复用方案、删除后受损的具体行为及验证依据。必要性以功能、正确性或资源回收损坏为依据，不要求整个程序崩溃，也不能人为制造依赖证明必要。

删除前核对直接调用、动态注册、SDK 回调、安装入口和既有接口，不能只凭文本搜索未命中。相似逻辑先检查共同职责，没有共同职责就不强行合并。异常处理须对应真实错误或可复现情形，在能恢复或准确报告的边界处理。

### 改造与审查

1. 改造前列明保留功能、故障证据、涉及职责、替代方案、预期有效行增删及必要的真实调用场景。
2. 实施中保留工具描述、权限、取消、资源回收和持久化语义；迁移须体现职责收益，不能仅更名或保留空代理。
3. 验收前核对模块、文件、有效行、净变化和异常处理依据。函数被调用、覆盖率或结构达标，均不能单独证明功能正确与职责必要。

## 测试与验收

### 环境和证据

验收范围、预算、轮数和服务目标按用户授权执行，不自行扩充。使用 Python 3.12 和明确指定的项目环境；安装制品回归使用授权的隔离目标，确认实际导入的是已安装 wheel。源码、pip、onedir 和 onefile 分别记录，不能互相替代。

回归应验证可观察行为，避免只复述实现。配置、网络故障和并发测试使用人工夹具；真实 API、embedding、rerank、模型输出、实际文件和终端操作单独验收，模拟结果不能冒充实际服务或账号收发。pytest 零收集视为失败，过期断言与跳过项说明原因，不通过删断言消除失败。

只改文档时检查事实、链接、约束和修改范围；涉及运行行为时执行对应回归和制品检查。源码、测试、题库或候选变化后，不能用其他候选的结果替代当前验证。

### 行为覆盖

- 配置覆盖三层四种命中情况、嵌套逐字段读取、命中后不读下层、合法空值/零/布尔值/空列表、非法值报错、dotenv 格式和无宿主环境业务覆盖；核对已有连接不重复询问、Esc 取消不保存及配置字节不变。
- 启动覆盖仅模型与连接配置、可选组件按需读取及输入界面可用。日志覆盖超过大小阈值仍追加、保留期边界、缺失和停用、直属日志与子目录区分、`.log.1` 保留，以及清理先于输入开放。
- 引用覆盖中文、空格、引号、相邻路径、重复与缺失文件、配置上限及超过上限、多条补充和最新纠正；核对真实内容及不可变快照。
- 在附件准备、工具、子 Agent、流式回复、压缩和加载期间执行停止、取消、清空或切项目，核对输入身份、调用配对、实际文件和资源回收。
- 暂停覆盖模型流、工具、子 Agent、提问、待解析引用及任务完成边界；核对派发顺序、补充保留、连续点击、草稿和焦点、重载后仍暂停，以及恢复不重发已提交任务或重跑已完成工具。
- 传输故障覆盖首段前、部分正文后、工具完成后的断开及 SDK 包装原因，检查部分正文、思考、用量、错误和证据保留，没有自动重跑或成功误报。
- 终端键鼠验证覆盖 Enter、Ctrl+Enter、LF、修饰 CR、粘贴、空白、重复提交、按钮锁定和思考框折叠。PyCharm Terminal 与 Windows Terminal 的物理按键、协议注入和模拟事件分别记录，不按名称宣布支持，不修改用户终端设置。
- 文件操作覆盖原子替换失败、并发审查、外部修改、路径越界与随包 Skills 只读；任务覆盖依赖、失败不自动排队及显式恢复；记忆覆盖并发版本冲突、投影失败、索引补全和证据保留。
- 记录 CPU、内存、Agent 线程、子进程、存储增长和积压，区分服务延迟与框架等待。

### 长会话验收条件

使用冻结题库和同一最终候选，在源码、pip、onedir 各完成 100 主会话回合和 20 跨会话回合，共 360 回合；核对五个记忆窗口、第 19 回合后的恢复，以及各入口至少三次真实阈值自动压缩。onefile 的启动和核心流程独立验收。

记忆核对新回合、overlap、ID、出处、更新、遗忘及跨项目边界。自动压缩按实际配置阈值触发，不能降低阈值或以手动压缩充数。开发题由 RedLotus 编写被测项目，验收者提出需求、纠偏并独立检查，不代写实现或补丁。

缓存按服务端 usage 统计，主 Agent 与普通子 Agent 总体命中率必须 **大于 90%**，包含冷请求、恢复及压缩后请求；标题、感知和压缩单列。缺失 usage 保持未知，不按零消耗计算，不预热或重复灌水凑数。

正常路径不得出现未预期的 WARNING/ERROR，故障注入和预期拒绝单列。首次失败和授权范围内纠偏后的结果分别保留，不更换失败题面、篡改答案、放宽断言或改变日志等级获取通过。未执行和豁免项目保持未验证，局部通过不证明长期稳定。

## 数据与清理

数据遵守[项目归属](README.md#数据归属)，项目会话、下载、依赖缓存和测试中间资料不迁入无关全局目录。测试使用明确的隔离项目和记忆命名空间，不改 HOME/USERPROFILE 或用目录链接掩盖归属。

onefile 包内资源由原生 bootloader 在启动环境选定的临时目录展开和清理，不改变业务数据归属，不在产品中硬编码机器路径。

临时项目、夹具、缓存、安装包和请求中间资料按授权清理。清理前核对解析后的绝对路径、所属范围和进程占用，不按目录名称猜测所有权，不删除正式会话、配置、引用、记忆或归属不明的产物。保留必要失败证据及脱敏结论，不把一次修复授权扩展为长期清理策略。

## 打包与交付

构建入口为 `scripts/pack.ps1`，支持 onedir 和 `-OneFile`，使用明确的已有解释器；构建目录、缓存和临时目录位于项目 runtime。制品须核对源码与资源一致性，排除私人配置、凭据、会话和运行数据。

发布入口为 `scripts/publish.ps1 -Version <版本> -ArtifactDirectory <已验收目录>`。制品目录须提供指定版本唯一的 wheel、sdist 及 `SHA256SUMS.txt`；脚本核对项目版本、包内元数据、哈希及 PyPI 是否已存在该版本，仅上传已验收文件，不改版本、不重建、不清空制品目录。Token 从项目 `.env` 取得，仅在发布子进程环境中使用，结束后恢复原环境值。

CI 的 `.github/workflows/auxiliary-checks.yml` 配置 Windows、Linux、macOS 的构建、安装和隔离回归；工作流定义不代表各平台或真实服务已验收。发布须另有明确授权，公开发布后核对下载哈希、全新安装、启动和核心流程，失败不得覆盖旧制品或宣称完成。

交付说明实际修改、原因、验证及限制；提交、推送、合并、发布分别遵守授权范围。分支与 worktree 清理前核对独有改动、合并状态和占用，不覆盖其他工作。

## 文档维护

`docs` 只保留总览、设计、开发约定三份文件。正文只描述项目事实、组件功能、开发偏好与硬性条件；同一规则在所属文档完整描述，其他位置链接引用。

变更经过、日期时间线、经验总结、提交号、测试成绩、制品指纹、阶段性结论和待办不进入设计稿，也不另建归档副本。有效公式、格式及验收门槛保留，不能与历史统计一起删除。规则变化直接改写相关条款，检查文档间一致性和链接有效性，不追加说明掩盖相反的现行要求。
