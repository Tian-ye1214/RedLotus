# RedLotus 开发习惯与偏好

> 来源：截至 2026-09-21 用户明确确认的要求及后续修订。面向维护者和 AI 协作者。新的明确指示可以更新本文；遇到冲突先指出具体差异，不用旧文档覆盖用户的新决定。

## 修改边界

1. 每项改动必须对应已确认功能；不擅自增加设计、限制、配置组、框架或后台服务。
2. 必要且已授权的工作继续完成，不反复索取同一确认；但新增有效代码必须按下文逐包审批。批准一个包不授权另一个包、扩大范围或增加预算。
3. 保留用户手工修改，不整体回滚工作区，不借修复覆盖用户恢复的提示词或配置。
4. 重构保留用户可观察行为和副作用，包含引用、diff、审查、goal、Skills、输入队列、恢复、统计和渠道权限。不能通过删除功能或断言达标。
5. 修复先定位原因并保留首次失败，再做最小改动和原场景重测；结果不确定就明确标注。
6. 当前代码与批准设计冲突时，将冲突写入[现行设计](design.md)，不要将错误实现反写成新需求。

## 配置与凭据

- 以用户当前配置为基础，先展示具体字段差异，得到批准后再改。不能为了“精简”只删必要字段；核查字段、读取入口、功能及实际效果。
- 模型名、服务地址、凭据、采样、输出、RAG、路径及可配置策略保持单一配置来源，读取后使用独立副本。禁止搬进代码、隐藏模板或借 SDK 默认值掩盖删除。
- **运行策略全部读配置。** 交互填写只处理模型选择、连接和凭据；上下文容量、压缩、重试、并发等策略不能要求用户在输入框补填。角色枚举复用现有配置读取入口，不另写 `ROLES` 或 `CONTEXT_ROLES` 常量。
- `models.<role>.max_context_windows` 缺失或为 `null` 时直接查询既有 OpenRouter metadata；正整数表示显式覆盖。不得因此弹出填写框、补隐藏默认容量或修改用户配置。元数据查询失败需如实报告，不能编造容量。
- 保留本地 JSON → 本地 `.env` → 全局 JSON 的优先级。缺项与类型错误应指出字段、来源及影响；不静默猜值、恢复废弃组或关闭功能。
- **禁止复制、备份、分发或上传 `config.json`、`.env`；禁止将配置或凭据作为模型材料。** 不建立含密钥的 private-config、测试配置、提示词、日志或请求副本。
- 验证使用现有配置读取入口和已批准的显式路径隔离；只记录来源、非敏感字段名及必要指纹，不输出密钥或整份合并配置。
- 不新增已拒绝的 `model_gateway`、`execution`、provider 或五种结果配置组。配置不能放提示词正文。
- 历史凭据事件的教训是：测试驱动也属于泄漏边界。不能把含凭据文件置于被测 Agent 可读的夹具中；清理本地副本不能撤回已外发信息。历史经过保留在 Git，不在新文档复制敏感材料。

### 已明确批准的业务例外

这些是具体批准项，不是任意硬编码的许可：

| 项目 | 已确认口径 |
| --- | --- |
| SDK 路由 | 模型名称采用“服务:模型”，由 Pydantic AI 路由；不新增 provider 字段 |
| 并行工具 | `parallel_tool_calls=True` 可直接写入模型设置 |
| 任务结果 | 成功、失败、取消、待输入、未验证属于业务定义，不另加配置组 |
| 执行保护 | 固定命令识别和既有进程误操作防护作为工具逻辑；不恢复 execution 配置或新增权限名单 |
| 线程与感知 | 已确认 16 线程、20 新回合＋3 overlap；从相应现有配置读取，不能改为隐藏常量 |

没有明确批准的参数或限制，不因“看起来合理”就加入。此前取消的 query、evidence、工具输出和标题长度限制，不得偷偷恢复；服务真实容量和已确认引用限制仍需准确报告。

## 提示词与工具

- 应用维护的提示词按已确认的英文要求编写，并保留完整任务约束；不要为省事简写。用户已经恢复的正文未经允许不修改、不新增，历史遗留差异不能私自修正。
- 提示词放资源文件，不能写入配置或在 Python 中隐藏补写。用户原文、引用和界面文案不强制翻译。
- system 必须保留 Skills、系统信息、行为约束、项目约束和长期记忆快照。记忆更新不重写同一会话的 system；恢复使用原快照。
- 每个 Agent 创建位置明确引用身份工具集合。英文函数 docstring 是唯一工具描述来源，签名、参数、返回和实际行为一致。
- Skills 正文渐进读取，执行经过统一入口；不通过外部 Markdown 动态覆盖工具描述或权限。
- Worker 保留结构化五种结果；Coordinator 直接委派的 Worker 有浏览器，Manager 委派的 Worker 没有浏览器。
- 保持工具层保护，不引入 Windows 权限库、系统 Hook 或插件来绕过终端／权限边界。PyCharm 插件方案已暂缓。

## 代码组织与精简

**代码简洁性始终是最高优先级，并同时纳入开发审批和验收审批：能用函数复用，绝不多写；能用类继承，绝不多写；能用原生库，绝不多写；能用一行代码解决，绝不多写。** 保持功能、正确性及可读性，不靠删除必要行为、挤行或隐藏实现达标。

- 基线原有 `core / tools / api / memory / prompts`；本轮已授权按运行时、模型、存储、终端等真实职责整理，现行划分见[模块职责](design.md#模块职责)。模块数不固定为六个，后续增加仍需具体方案审批，不能仅为分摊行数拆文件。
- 最终验收原则上每个模块递归最多 **5 个 `.py` 文件**（含 `__init__.py`），每文件最多 **500 有效代码行**；同时报告物理行数。有效行排除空行、注释及 docstring，不删除工具描述来达标。现有超限列为待整改，不能宣称已经符合；任何例外单独报用户批准。
- 测试、打包脚本和随包 Skills 脚本单独计数，不允许把应用实现转移进去规避模块限制，也不能藏入字符串、模板或代码生成。中间步骤可保留基线超限，最终审批必须逐文件核对。
- 每一新增有效代码行必须能对应已批准需求、真实问题及必要行为；每个函数承担一个独立职责。发现相似行为，先检查现有函数、适用的继承和标准库，说明不能复用的具体原因后才保留新实现。
- 写 `try/except` 前确认：是在处理已观察或已复现的错误，还是预防假设？没有发生过、也没有复现依据的假设不增加捕获分支。真实错误只在有能力处理的边界捕获；资源释放优先用现有上下文管理器，不包裹整条正常流程。
- 不擅自把代码 A 搬到新文件 B，不用一组导出或 `sys.modules` 别名掩盖迁移。确需迁移时，审批中列出原位置、新位置、调用方和具体收益；兼容仅保留已确认仍有效的外部入口。
- 删除接口前核对直接调用、动态注册、SDK 回调及安装入口。简化前后核验实际行为、副作用和资源归属，不修改用户配置或提示词资源来使检查通过。

### 开发与验收审批

**本轮授权（2026-09-21）：**用户已授权全部已列整改包，要求在开发分支完成可交付、可合并的版本，次日统一审查。本轮这些包及其必要的集成、精简、测试和分发验证连续实施，不再逐包索取确认；仍记录实际增删、复用理由和验证结果。此授权不包含公开发布、推送或合并，也不允许改写私人配置和提示词资源。后续新范围仍遵守下述审批规则。

1. **开发前：**每个变更包列出需求／故障证据、文件与函数、具体拟改内容、复用或标准库方案、替代方案为何不够、毛新增／毛删除有效行数上限、物理行数及文件数影响、真实 API 场景。净删行的包只要新增有效代码，同样先审批；新测试和辅助实现也不能绕过。
2. **得到该包确认后实施：**不将“执行计划”解释为后续所有新增代码的无限授权。范围、文件或新增预算超出已批内容时，先完成可审查方案，再申请变更；不先落盘后补批。本轮明确授权的回滚和文档更新直接完成。
3. **验收前：**审查实际 diff，逐段解释每行必要性，逐函数核对单一职责及相似实现是否复用，列出新增异常分支的复现依据，报告每模块文件数与每文件有效／物理行数。文字承诺或只有数字达标不能代替审查。
4. **验收结论：**逐项附对应真实 API、真实入口、产物、恢复与资源证据；辅助检查单列。超限、未解释的重复、未批准新增代码或未执行场景必须保留待办，不标为 LGTM。

### 必须纳入审查的具体案例

| 案例 | 审查要求 |
| --- | --- |
| 新增 `runtime/cancellation.py` | 先问是否来自需求、现有保存调用和原生取消状态能否解决、是否只需一个表达式。取消保存死锁仍要修，不能先建立独立框架再寻找用途。 |
| 硬编码 `ROLES`／`CONTEXT_ROLES` | 复用配置及现有 `get_agent_roles`／`get_context_profile_roles`；新增模型或身份不应再维护第二份角色名单。 |
| `core/presentation.py` 中一组仅 `return emit("…", *args, **kwargs)` 的包装 | 复用一个入口、已有对象方法或标准库绑定；不为同一转发行为展开十个函数。 |
| 将 `tools/worker_tools.py` 搬到新文件再留下别名 | 已要求完整复原；后续修改先在原职责位置简化，迁移必须单独说明收益并获批。 |
| 未发生问题就添加 `try/except` | 提交真实故障或复现证据，说明捕获处怎样恢复；没有依据就不加。 |

正式程序不保留按键检测页面、按钮或启动探测；测试阶段的临时检测单独执行，不随包发布。PyCharm 无法区分 Ctrl+Enter 时沿用底部已有的“发送”操作，不新增全局键盘 Hook 或另一套快捷键。

## 真实验收习惯

### 真实 API 是必需条件

- 今后每次功能测试、缺陷复测和发布验收，都必须从真实产品入口调用真实服务 API，以第一次使用 RedLotus 的新用户视角完成当轮场景。此要求同时适用于维护者和 AI 协作者。
- “模拟用户”指按用户方式安装、配置、输入需求、操作界面和检查结果；不能模拟模型或服务响应。涉及主 Agent、Manager、Worker、标题、压缩、感知、embedding 或 rerank 的场景，应实际走通对应调用链，单独请求一次 API 不能证明产品调度通过。
- 单元测试、mock／TestModel、故障注入、静态检查、导入检查、离线页面及构建检查仅作为定位问题和保护代码的辅助检查。可以保留并运行，但不能单独据此宣布“测试完成”“功能通过”“发布通过”或 LGTM。
- 缺少真实账号、网络、额度或对应运行环境时，将受影响场景标为未执行或阻塞，说明缺少的条件；不得换成模拟响应后计为通过。此前“先完成离线修复”的阶段性安排只说明历史执行范围，不是后续测试的默认方式。

### 环境与范围

优先用户日常真实环境，不自行另造替代环境：

| 环境 | 已确认位置或入口 |
| --- | --- |
| 项目源码 | `E:\代码\Agent\.venv`，运行项目 `main.py` |
| 日常 pip | `D:\Software\miniconda\python.exe`，通过 CMD 的 `redlotus` 启动 |
| 打包程序 | 实际构建、解压的 PyInstaller 制品；当轮交付的 onedir／onefile 分别启动并完成真实调用 |

工具不自动创建 venv；依赖安装明确实际解释器、目标和影响，不把依赖装到其他环境。新增组件、插件、参数变更或可能影响其他软件的依赖操作，遵循具体授权。

验收轮数、预算、期限和阶段以当轮批准方案为准，不自行扩充。定向测试同样必须使用真实 API；缩小当轮范围不等于取消真实调用要求。原三环境全量目标仍是每环境 100 主会话＋20 跨会话、合计 360 轮，局部通过不等于全量门槛已通过或已取消。

### 按新人用户完成流程

1. 在明确隔离的测试项目中，从 README 的安装说明开始，记录实际版本、解释器、启动目录及入口。使用面向用户的安装命令，不依赖开发者预置会话、记忆、任务状态或未写入文档的补救步骤。
2. 从首次配置开始体验文档、模型／连接／凭据交互及错误提示，运行策略按配置读取，通过现有安全配置入口使用当轮已授权的真实服务与账号；不复制私人配置，不向被测 Agent 提供凭据。不能假装已有完整空配置向导；无法完成的步骤记录为缺陷。
3. 按普通用户方式启动 `main.py`、已安装包的 `redlotus` 或实际 EXE，用自然语言提出任务、补充要求、纠错及确认。通过这些入口触发真实调度、模型调用、工具执行和相关辅助角色，不直接调用内部函数或改写状态来代替用户流程。
4. 独立检查回复、实际文件、工具产物、任务状态及服务端用量；通过用户可用的命令执行停止、清空、退出、重新启动、恢复和跨会话操作。不提前填入预期摘要、记忆或完成结果。
5. pip 候选包的本地安装与公开发布分别留证。声称“新 pip 版本发布并验证”前，必须在已有发布授权范围内实际发布，再从发布索引安装该版本，核对安装来源，并通过 `redlotus` 完成真实 API 流程；同时验证既定的全新安装与旧版升级场景。源码、editable 安装或本地 wheel 替换不能替代该结论。
6. PyInstaller 构建后，在源码目录外直接运行当轮交付的 onedir／onefile，完成配置、真实 API 对话、任务／工具、退出与恢复。构建成功、资源完整或缺配置启动报错，只能记为构建辅助检查通过。

### 场景与证据

每个变更包按影响选择下表场景，最终验收覆盖全部维度；不以一次成功对话代替多维度、多角度测试。

| 维度 | 实际检查 |
| --- | --- |
| 用户与入口 | 新用户安装、配置、普通／加急输入、补充、按钮及命令；源码、日常 pip、实际 onedir／onefile 分开运行 |
| 调度与服务 | 主 Agent、直接 Worker、Manager 依赖任务、辅助角色；实际配置的模型协议、工具调用与服务端 usage |
| 生命周期 | 成功、失败、待输入、取消、未验证；停止、清空、切项目、退出后恢复，确认没有重复副作用 |
| 并发与边界 | 慢附件、连续输入、多附件部分失败、写文件期间外部编辑、逆序记忆提交、索引缺失及压缩边界 |
| 数据与资源 | 实际文件／记忆、提示词快照、输入与用量去重、浏览器／子进程／线程释放、长期积压 |
| 分发与平台 | 全新安装、真实版本升级、制品资源与凭据排除；Windows／Linux／macOS 按可用真实环境留证 |

真实服务失败不可控时，可用故障注入辅助定位该分支，但不得把注入结果记为真实服务故障验收通过。纯文档与回滚的内容一致性检查如实标为辅助检查，不虚构 API 调用。

- 模拟从缺配置、安装、启动到对话、工具、退出和恢复的真实流程。源码通过不能替代 pip 或 EXE 通过，候选替换不能冒充版本升级。
- 重点覆盖不规范输入：无引号／相邻多文件、中文与空格路径、重复与缺失引用、20／21 文件边界、连续 5–6 条补充及最新纠正。
- 在慢附件、工具运行、流式回复、压缩和加载期间执行停止、清空、取消或切项目，核对实际输入 ID、请求边界、调用配对和文件内容。
- Ctrl+Enter 必须区分物理按键、终端协议注入和直接设置 urgent 参数的测试；新环境用检测结果，不按终端名称宣布支持。
- 开发题由 RedLotus 编写被测项目，测试者只提出需求、纠偏和独立验收，不代写实现或补丁。
- 真实模型、embedding、rerank、工具、产物与终端证据和本地辅助检查分别报告。人工夹具不能冒充真实感知生产。
- 自动压缩按实际阈值验证，不降低阈值或使用手动压缩充数。记忆校验新回合、overlap、ID、出处、更新、遗忘和跨项目边界。
- 缓存使用服务端 usage。主 Agent＋普通子 Agent 的总体目标 >90%，包含冷请求、恢复与压缩后请求；标题、感知、压缩单列，不预热或重复灌水凑数。
- 正常路径零个未预期 WARNING／ERROR；故障注入和预期拒绝单列。缺 usage、超时、未执行、外部阻塞和失败如实保留。
- 保存首次结果及批准次数内纠偏后的结果；不更换失败题面、篡改答案、放宽断言或修改日志等级获得通过。
- 记录 CPU、内存、Agent 线程、子进程、存储增长和积压。真实 API 延迟与框架等待分开定位；局部通过不能证明长期无资源问题。

## 数据与清理

项目会话和日志属于项目 `.redlotus`，产物、引用与 runtime 属于项目 `WorkDatabase`。全部 LanceDB 记忆库可使用用户 `.redlotus`；不能把项目会话、下载、依赖或测试中间产物转移到 C、D 盘全局目录。

测试临时资料少量放 E 盘，记忆使用用户数据目录内明确的独立测试命名空间。不要通过改 HOME／USERPROFILE 掩盖路径，亦不以目录链接替代真实归属。

测试通过后清理已确认的临时项目、夹具、依赖缓存、安装包、build／dist 和完整请求中间记录；失败只保留必要的最小复现和脱敏结论。清理前核对绝对路径、所属范围与进程占用，不按目录名字猜测是否测试数据，不删除正式会话、配置、引用、记忆或归属不明的产物。不把一次磁盘修复授权泛化为日常清理流程。
