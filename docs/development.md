# RedLotus 开发习惯与偏好

> 来源：截至 2026-09-23 用户明确确认的要求及后续修订。面向维护者和 AI 协作者。新的明确指示可以更新本文；遇到冲突先指出具体差异，不用旧文档覆盖用户的新决定。

## 修改边界

1. 每项改动必须对应已确认功能；不擅自增加设计、限制、配置组、框架或后台服务。
2. 必要且已授权的工作继续完成，不反复索取同一确认；有实际设计分歧时说明具体差异、用途、原因和影响，再确认。
3. 保留用户手工修改，不整体回滚工作区，不借修复覆盖用户恢复的提示词或配置。
4. 重构保留用户可观察行为和副作用，包含引用、diff、审查、goal、Skills、输入队列、恢复、统计和渠道权限。不能通过删除功能或断言达标。
5. 修复先定位原因并保留首次失败，再做最小改动和原场景重测；结果不确定就明确标注。
6. 当前代码与批准设计冲突时，将冲突写入[现行设计](design.md)，不要将错误实现反写成新需求。

本轮执行用户批准的 `1.0.1-release` 计划：在 develop 开发和验收，全部未豁免门槛通过后才合入 master、建立 `v1.0.1.post1` 并发布 Python 包 `1.0.1.post1`。既有线上 1.0.1 保留。Linux、macOS、真实 QQ／微信账号和未配置协议仅豁免本轮真实验收，不能删除实现或写成已验证。2026-09-22 用户明确删除旧版 1.0.1 的启动、兼容配置及升级测试验收，不添加其已废弃的 max_tool_output_chars 或其他兼容策略值。公开新版 PyPI 全新安装与 GitHub 实际下载验收在发布后单独执行；失败必须保留，不宣布发布验收成功。

## 配置与凭据

- 以用户当前配置为基础，先展示具体字段差异，得到批准后再改。不能为了“精简”只删必要字段；核查字段、读取入口、功能及实际效果。
- 模型名、服务地址、凭据、采样、输出、RAG、路径及可配置策略保持单一配置来源，读取后使用独立副本。禁止搬进代码、隐藏模板或借 SDK 默认值掩盖删除。
- 保留本地 JSON → 本地 `.env` → 全局 JSON 的优先级。缺项与类型错误应指出字段、来源及影响；不静默猜值、恢复废弃组或关闭功能。
- **禁止复制、备份、分发或上传 `config.json`、`.env`；禁止将配置或凭据作为模型材料。** 不建立含密钥的 private-config、测试配置、提示词、日志或请求副本。
- 验证使用现有配置读取入口和已批准的显式路径隔离；只记录来源、非敏感字段名及必要指纹，不输出密钥或整份合并配置。
- 不新增已拒绝的 `model_gateway`、`execution`、provider 或五种结果配置组。配置不能放提示词正文。
- 历史凭据事件的教训是：测试驱动也属于泄漏边界。不能把含凭据文件置于被测 Agent 可读的夹具中；清理本地副本不能撤回已外发信息。历史经过保留在 Git，不在新文档复制敏感材料。

## 提示词与工具

- 应用维护的提示词按已确认的英文要求编写，并保留完整任务约束；不要为省事简写。用户已经恢复的正文未经允许不修改、不新增，历史遗留差异不能私自修正。
- 提示词放资源文件，不能写入配置或在 Python 中隐藏补写。用户原文、引用和界面文案不强制翻译。
- system 必须保留 Skills、系统信息、行为约束、项目约束和长期记忆快照。记忆更新不重写同一会话的 system；恢复使用原快照。
- 每个 Agent 创建位置明确引用身份工具集合。英文函数 docstring 是唯一工具描述来源，签名、参数、返回和实际行为一致。
- Skills 正文渐进读取，执行经过统一入口；不通过外部 Markdown 动态覆盖工具描述或权限。
- Worker 保留结构化五种结果；Coordinator 直接委派的 Worker 有浏览器，Manager 委派的 Worker 没有浏览器。
- 保持工具层保护，不引入 Windows 权限库、系统 Hook 或插件来绕过终端／权限边界。PyCharm 插件方案已暂缓。

## 代码组织与精简

**代码简洁性始终是最高优先级：能用函数复用，绝不多写；能用适当继承复用，绝不多写；能用标准库，绝不多写。功能完整、正确和可读是前提，不能硬删功能、揉成大函数或隐藏实现来减少数字。**

- 应用原则上保持现有六个模块。用户于 2026-09-21 允许确有必要时新增一至两个模块，**总数最多 8 个**；新增模块须记录职责、必要性、替代与复用方案、依赖收益。该授权不允许任意拆分或新增第九个模块。
- 每模块递归最多 **5 个 `.py` 文件**，包含 `__init__.py`；每个文件最多 **500 有效代码行**。这些约束同时适用于功能改造审批和测试验收审批，不以中间步骤达标冒充最终达标。
- 空行、注释不计，多行参数和语句续行合计一行；说明文档字符串不计。不能通过分号堆叠、压缩排版、嵌套目录、外移业务代码或动态执行字符串规避。
- **物理行数不设上限**，只作可读性参考，不再以物理行数超过 500 报告违规。有效行统一依据 Python 逻辑语句换行统计；函数、类和装饰器同样计入。
- 第三方 Skills 资源不计入自有业务文件；自有工具、Skills 管理器和业务实现必须计入。
- 测试与打包脚本单独报告，不得承载被挪出的应用实现。自有测试每组最多 5 个 Python 文件、每文件最多 500 有效行，不能通过拆分测试组掩盖重复。
- 删除函数前核对直接调用、动态注册、SDK 回调、安装入口和既有接口，不能仅因文本搜索未命中就删除。
- 优先复用队列、会话控制器、工厂、存储事务和工具检查；减少重复状态与无职责包装，不另建调度框架。
- 每个函数记录唯一职责、调用方或注册入口、不能由现有实现取代的原因、删除后受损的具体行为以及验证证据。用户已确认：必要性以具体功能、正确性或资源回收损坏为依据，不要求整个程序立即崩溃。
- 相似逻辑先考虑共享函数、标准库或有实际替换关系的继承；没有共同职责就不强行合并。禁止为了证明必要性人为制造依赖或崩溃。
- 写 `try/except` 前记录真实错误或可复现依据；在能够恢复或准确报告的边界处理，不添加假设性的兜底分支。
- 本轮完整撤回 12 模块版本后从 `ca98b811` 重做。功能保留，修复既有缺陷，不扩展产品功能；应用有效行净减少，代码 diff 的删除行数必须大于新增行数，不能靠删除说明或测试凑数。

回滚基线实测为 29 个应用 Python 文件、10,373 个有效行、1,065 个函数定义；core 10 文件、tools 7 文件，config／console／session／system／tui／references 超过 500 有效行。这是重做基线。`f32c3217` 的八模块整合为 36 个应用 Python 文件、10,348 有效行、991 个函数定义及 81 个 lambda，每模块最多 5 文件、单文件最多 500 有效行。相对基线，应用 Python 的 Git 毛新增为 6,541 行、毛删除为 6,691 行（含真实迁移及 Git 重命名识别）；有效行净少 25 行。结构及净减少门槛通过，逐函数必要性／正交性审查仍未完成，不能以这些数字代替功能证明。此前 12 模块版本的测试和制品不作为重做版本的通过证据。

### 功能改造与测试验收审批

停止回执的整改案例（2026-09-23）：真实渠道请求证明旧 `/stop` 回执会被追加到下一条保留消息。复用会话已有的代次和回合 ID，必须在等待取消前捕获，避免新回合先开始；消费时按同一身份筛选。删除提前捕获或筛选都会把已取消状态带入新请求。两个旧实现的失败、停止／清空参数化回归及相同渠道的真实 API 复测支撑这项修改；未增加函数、配置或模块，应用仍为 10,365 有效行。

1. **改造前：**列出保留功能、故障证据、模块／文件／函数、替代与复用方案、预期有效行增删及真实 API 场景。新增模块必须明确审批；现有授权只允许职责必要的第七、第八个模块，不能突破八模块上限。
2. **实施中：**先记录现有行为与失败，再做最小修改；功能、工具描述、权限、资源回收及持久化语义保持完整。迁移必须体现职责收益，不能仅换文件名；`tools/worker_tools.py` 保留真实执行实现，不留下别名伪装。
3. **验收前：**逐模块核对最多 8／5／500（第七、第八模块另附必要性），逐函数核对职责和必要性；核对实际毛新增、毛删除及净变化，并审查异常处理依据。函数被调用或覆盖率通过，单独不足以证明正交与必要。
4. **行为验收：**从真实源码、pip 和实际打包入口调用真实 API，核对已有功能、输出、恢复、权限和资源；隔离回归、故障注入和删除函数的反事实验证仅为辅助证据。未覆盖项保持未完成，禁止借结构达标宣称没有隐形 bug。

### 具体精简审查案例

- `runtime/cancellation.py`：先核对原生取消状态和现有持久化参数能否解决实际死锁；不能为尚不存在的问题建立框架。
- `ROLES`／`CONTEXT_ROLES`：从配置读取已定义身份，不能维护另一份角色清单。
- `core/presentation.py` 的重复转发函数：复用统一入口或标准库绑定，保留对应展示行为；不展开多份只改事件名的函数。
- 按键检测仅用于测试；正式发布移除检测页面和按钮，不修改终端设置或添加系统键盘 Hook。

### 本轮新增函数的必要性证据

以下只覆盖本批整改，不代表已完成全项目逐函数审查。

`bef1a9e4` 的命令修复仅给现有子进程参数增加 `stdin=asyncio.subprocess.DEVNULL`，没有新增应用函数或文件。真实升级测试中，活动 CLI 输入线程使 Python 子命令一直等待，普通 echo 则成功；原生有／无 stdin 对照和 shell／exec 两个 EOF 反事实均重现。源码及安装包随后各三轮真实 API，命令输出、Worker 回执、恢复及进程退出均核对；见 `stdin-independent-verification.json`。该行复用标准库，解决实际故障，没有另建进程包装层。

`bf73c3a3` 复用 RequestPolicy 和现有压缩候选，新增 12 个有效行、不增加应用函数或文件。有限重试和容量错误识别防止普通 400 被重放；压缩期间移除活动模型请求身份，避免取消账本虚增请求；候选先保存、再同步 SDK 消息，保存失败或取消均不得继续发送。能力链把请求策略放在计时器外层，两次实际请求各有计时记录；唯一输入消息仅在明确强制压缩时可压缩，system 与工具定义不进入摘要。上述行为由原始 pip／onedir 容量错误及 16 项定向红绿支撑，独立源码审查见 `first-capacity-review.json`。

前版 `bf73c3a3` 的源码及实际安装 wheel 各 **207 项辅助回归通过**。首轮沙箱有两项 taskkill 权限失败，原生权限重跑相同测试通过，原日志保留；测试驱动的错误导入和非应用流式入口也保留并修正。真实原窗口恢复另记，离线通过不代替 API 结果。`necessity-current-review-coverage.json` 精确核对了 `1ee66723` 相比旧审查变化的 111 项 callable（55＋56）及 961 项未变 AST；后续两次改动单独审查。所有删除影响均区分源码推导和实际反事实，仍未宣称全项目逐行证明完成。

`f32c3217` 的 PDF 修复在原读取函数末尾追加原生 `page.get_links()`，新增 3 个有效行，没有新增函数或文件；追加顺序保持已有文本／图片部件编号，解析器版本 4 使旧缓存重新解析。移除这三行会重现真实 API 无法取得目标地址；不升级缓存版本会使同一旧引用继续遗漏；把链接插入正文中间会改变已有图片索引。原生链接／内部跳页／旧缓存／图片编号的红绿回归和同一旧会话真实复测均保留。使用主入口 `pymupdf` 消除了已观察到的 `fitz` 弃用警告，未增加兼容包装。源码和隔离环境已安装 wheel 各 210 项辅助回归通过；实际 pip 及两个 EXE 的六项文档核对均通过，EXE 另有 Worker／浏览器／恢复真实调用。测试导入去重复用，应用和测试均满足 8／5／500。

0.8 配置变更有单独逐字段核对：`configuration-ratio-08-approval.json` 记录三个获批值及前后指纹，其他值逐项相同，其余 13 项保护文件指纹未变。配置不提交或打包。553,173 输入 Token 的原 pip 会话真实触发压缩后下一请求为 127,517，system 与旧用量保持；边界辅助测试核对 504,627 不触发、504,628 触发。初始压缩器超限与连续对话阈值分别验收，不能混为一项通过。

制品测试不能只采信模型的“执行成功”回复。`f32c3217` 两个 EXE 的额外取证回合在 Worker 清理前读取原始工具调用／返回对，再与实际产物逐字节核对；浏览器截图按真实工具回执定位，不能猜测文件名。驱动的编码、观察时机及私有属性错误均在测试证据中保留，不为修复驱动增加应用包装代码。

本次输入预算修改仅新增 `_compression_threshold` 一个共享纯函数，应用净增 3 有效行、没有新增文件。界面、候选检查、请求边界是三个消费者；退回旧公式会把测试触发点从 54 延至 90，并重现真实总容量冲突。复用既有 `Decimal` 和标准库 `ceil`：浮点版在 25×0.28 的边界错误返回 8，十进制版按约定返回 7。配置仍从现有入口解析，持久化模型快照提供请求时的输出预算；`necessity-input-budget-delta.json` 记录故障对照、复用方案、配置来源及独立复核。该证据不等于全项目逐行或正交性证明。
