# RedLotus 开发习惯与偏好

> 来源：截至 2026-09-21 用户明确确认的要求及后续修订。面向维护者和 AI 协作者。新的明确指示可以更新本文；遇到冲突先指出具体差异，不用旧文档覆盖用户的新决定。

## 修改边界

1. 每项改动必须对应已确认功能；不擅自增加设计、限制、配置组、框架或后台服务。
2. 必要且已授权的工作继续完成，不反复索取同一确认；有实际设计分歧时说明具体差异、用途、原因和影响，再确认。
3. 保留用户手工修改，不整体回滚工作区，不借修复覆盖用户恢复的提示词或配置。
4. 重构保留用户可观察行为和副作用，包含引用、diff、审查、goal、Skills、输入队列、恢复、统计和渠道权限。不能通过删除功能或断言达标。
5. 修复先定位原因并保留首次失败，再做最小改动和原场景重测；结果不确定就明确标注。
6. 当前代码与批准设计冲突时，将冲突写入[现行设计](design.md)，不要将错误实现反写成新需求。

## 配置与凭据

- 以用户当前配置为基础，先展示具体字段差异，得到批准后再改。不能为了“精简”只删必要字段；核查字段、读取入口、功能及实际效果。
- 模型名、服务地址、凭据、采样、输出、RAG、路径及可配置策略保持单一配置来源，读取后使用独立副本。禁止搬进代码、隐藏模板或借 SDK 默认值掩盖删除。
- 保留本地 JSON → 本地 `.env` → 全局 JSON 的优先级。缺项与类型错误应指出字段、来源及影响；不静默猜值、恢复废弃组或关闭功能。
- **禁止复制、备份、分发或上传 `config.json`、`.env`；禁止将配置或凭据作为模型材料。** 不建立含密钥的 private-config、测试配置、提示词、日志或请求副本。
- 验证使用现有配置读取入口和已批准的显式路径隔离；只记录来源、非敏感字段名及必要指纹，不输出密钥或整份合并配置。
- 不新增已拒绝的 `model_gateway`、`execution`、provider 或五种结果配置组。配置不能放提示词正文。
- 历史凭据事件的教训是：测试驱动也属于泄漏边界。不能把含凭据文件置于被测 Agent 可读的夹具中；清理本地副本不能撤回已外发信息。历史经过保留在 Git，不在新文档复制敏感材料。

### 已明确批准的业务例外

这些是具体批准项，不是任意硬编码的许可：

| 项目 | 已确认口径 |
| --- | --- |
| SDK 路由 | 模型名称采用“服务:模型”，由 Pydantic AI 路由；不新增 provider 字段 |
| 并行工具 | `parallel_tool_calls=True` 可直接写入模型设置 |
| 任务结果 | 成功、失败、取消、待输入、未验证属于业务定义，不另加配置组 |
| 执行保护 | 固定命令识别和既有进程误操作防护作为工具逻辑；不恢复 execution 配置或新增权限名单 |
| 线程与感知 | 已确认 16 线程、20 新回合＋3 overlap；从相应现有配置读取，不能改为隐藏常量 |

没有明确批准的参数或限制，不因“看起来合理”就加入。此前取消的 query、evidence、工具输出和标题长度限制，不得偷偷恢复；服务真实容量和已确认引用限制仍需准确报告。

## 提示词与工具

- 应用维护的提示词按已确认的英文要求编写，并保留完整任务约束；不要为省事简写。用户已经恢复的正文未经允许不修改、不新增，历史遗留差异不能私自修正。
- 提示词放资源文件，不能写入配置或在 Python 中隐藏补写。用户原文、引用和界面文案不强制翻译。
- system 必须保留 Skills、系统信息、行为约束、项目约束和长期记忆快照。记忆更新不重写同一会话的 system；恢复使用原快照。
- 每个 Agent 创建位置明确引用身份工具集合。英文函数 docstring 是唯一工具描述来源，签名、参数、返回和实际行为一致。
- Skills 正文渐进读取，执行经过统一入口；不通过外部 Markdown 动态覆盖工具描述或权限。
- Worker 保留结构化五种结果；Coordinator 直接委派的 Worker 有浏览器，Manager 委派的 Worker 没有浏览器。
- 保持工具层保护，不引入 Windows 权限库、系统 Hook 或插件来绕过终端／权限边界。PyCharm 插件方案已暂缓。

## 代码组织与精简

**代码简洁性始终是最高优先级：能用函数复用，绝不多写；能用适当继承复用，绝不多写；能用标准库，绝不多写。功能完整、正确和可读是前提，不能硬删功能、揉成大函数或隐藏实现来减少数字。**

- 应用原则上保持现有六个模块。用户于 2026-09-21 允许确有必要时新增一至两个模块，**总数最多 8 个**；新增模块须记录职责、必要性、替代与复用方案、依赖收益。该授权不允许任意拆分或新增第九个模块。
- 每模块递归最多 **5 个 `.py` 文件**，包含 `__init__.py`；每个文件最多 **500 有效代码行**。这些约束同时适用于功能改造审批和测试验收审批，不以中间步骤达标冒充最终达标。
- 空行、注释不计，多行参数和语句续行合计一行；说明文档字符串不计。不能通过分号堆叠、压缩排版、嵌套目录、外移业务代码或动态执行字符串规避。
- **物理行数不设上限**，只作可读性参考，不再以物理行数超过 500 报告违规。有效行统一依据 Python 逻辑语句换行统计；函数、类和装饰器同样计入。
- 第三方 Skills 资源不计入自有业务文件；自有工具、Skills 管理器和业务实现必须计入。
- 测试与打包脚本单独报告，不得承载被挪出的应用实现。自有测试每组最多 5 个 Python 文件、每文件最多 500 有效行，不能通过拆分测试组掩盖重复。
- 删除函数前核对直接调用、动态注册、SDK 回调、安装入口和既有接口，不能仅因文本搜索未命中就删除。
- 优先复用队列、会话控制器、工厂、存储事务和工具检查；减少重复状态与无职责包装，不另建调度框架。
- 每个函数记录唯一职责、调用方或注册入口、不能由现有实现取代的原因、删除后受损的具体行为以及验证证据。用户已确认：必要性以具体功能、正确性或资源回收损坏为依据，不要求整个程序立即崩溃。
- 相似逻辑先考虑共享函数、标准库或有实际替换关系的继承；没有共同职责就不强行合并。禁止为了证明必要性人为制造依赖或崩溃。
- 写 `try/except` 前记录真实错误或可复现依据；在能够恢复或准确报告的边界处理，不添加假设性的兜底分支。
- 本轮完整撤回 12 模块版本后从 `ca98b811` 重做。功能保留，修复既有缺陷，不扩展产品功能；应用有效行净减少，代码 diff 的删除行数必须大于新增行数，不能靠删除说明或测试凑数。

回滚基线实测为 29 个应用 Python 文件、10,373 个有效行、1,065 个函数定义；core 10 文件、tools 7 文件，config／console／session／system／tui／references 超过 500 有效行。这是重做基线。最新八模块整合为 36 个应用 Python 文件、10,322 有效行、998 个函数定义，每模块最多 5 文件、单文件最多 498 有效行。相对基线，应用 Python 的 Git 毛新增为 5,794 行、毛删除为 5,910 行（含真实迁移）；有效行净少 51 行。结构及净减少门槛通过，逐函数必要性／正交性审查仍未完成，不能以这些数字代替功能证明。此前 12 模块版本的测试和制品不作为重做版本的通过证据。

### 功能改造与测试验收审批

1. **改造前：**列出保留功能、故障证据、模块／文件／函数、替代与复用方案、预期有效行增删及真实 API 场景。新增模块必须明确审批；现有授权只允许职责必要的第七、第八个模块，不能突破八模块上限。
2. **实施中：**先记录现有行为与失败，再做最小修改；功能、工具描述、权限、资源回收及持久化语义保持完整。迁移必须体现职责收益，不能仅换文件名；`tools/worker_tools.py` 保留真实执行实现，不留下别名伪装。
3. **验收前：**逐模块核对最多 8／5／500（第七、第八模块另附必要性），逐函数核对职责和必要性；核对实际毛新增、毛删除及净变化，并审查异常处理依据。函数被调用或覆盖率通过，单独不足以证明正交与必要。
4. **行为验收：**从真实源码、pip 和实际打包入口调用真实 API，核对已有功能、输出、恢复、权限和资源；隔离回归、故障注入和删除函数的反事实验证仅为辅助证据。未覆盖项保持未完成，禁止借结构达标宣称没有隐形 bug。

### 具体精简审查案例

- `runtime/cancellation.py`：先核对原生取消状态和现有持久化参数能否解决实际死锁；不能为尚不存在的问题建立框架。
- `ROLES`／`CONTEXT_ROLES`：从配置读取已定义身份，不能维护另一份角色清单。
- `core/presentation.py` 的重复转发函数：复用统一入口或标准库绑定，保留对应展示行为；不展开多份只改事件名的函数。
- 按键检测仅用于测试；正式发布移除检测页面和按钮，不修改终端设置或添加系统键盘 Hook。

### 本轮新增函数的必要性证据

以下只覆盖本批整改，不代表已完成全项目逐函数审查。

基础设施整改保留原调用语义：`runtime.config` 负责配置快照、覆盖与最小写回；`resources` 负责工作区和文件操作；`network` 负责模型连接与各循环 HTTP 池；`logging` 通过注入的展示函数输出。日志级别共享 `_emit`，用原生 `functools.partial` 绑定，删除五个重复包装函数。读取配置不加载 Agent、终端或记忆层；隔离子进程验证这一边界，连接池测试验证子线程退出不会关闭父循环客户端，会话清理测试验证活动与当前会话保留。

| 函数／接口 | 唯一职责与复用关系 | 删除或绕过后的具体损坏与证据 |
| --- | --- | --- |
| `TaskManager.save` | 在会话循环内串行保存计划快照，复用现有会话持久化接口 | 未保存 A 完成状态就能派发 B；隔离测试阻塞保存并核对 B 尚未执行 |
| `TaskManager.start`／`finish` | 分别记录派发的真实输入边界和归一化执行结果，均复用 `save` | 恢复会丢失运行状态、产物或结果；取消与未验证可能误入失败重试；状态和恢复回归覆盖 |
| `TaskManager.resume`／`AgentSystem.resume_task` | 前者校验新输入并恢复指定状态；后者连接真实会话输入、已存 Worker 对话和现有调度器 | 原有待输入任务无恢复入口；A／B／C 场景验证只恢复 A，再允许 B，C 结果保留 |
| `AgentSystem._save_tasks` | 把计划快照写入当前所属会话，复用 `_durable_write` | 工具层无法在模型请求前完成持久化，也会失去既有磁盘暂停／取消语义 |
| 子 Agent `save_context` 回调 | 普通检查点和压缩候选共用保存与身份校验 | 保存失败仍可能发送下一次模型请求；Worker／Manager 故障注入均验证后续请求未发生 |
| `LongTermMemory.project_record` | 纯计算投影并检查生成后外部编辑，供首次提交和重试共用 | 删除预检会覆盖手工修改或其他记录；外部编辑及跨记录替换回归明确拒绝且保留原文件 |
| `MemoryService._publish` | 把同一候选依次提交正式数据库、任务阶段和原子投影，复用现有任务与文件接口 | 旧顺序会注入未提交内容；分阶段故障回归和真实重启重试核对正式版本、投影及不增加模型调用 |
| `LongTermMemory.publication_lock`／`get_injection` | 前者共享提交、清空、新会话读取互斥；后者只注入正式版本匹配的托管块 | 绕过校验会把未提交或已过期块注入新会话；版本不符回归保留磁盘原文但排除错误注入 |

| `SessionJournal` / `SessionFile` | 前者集中事务与损坏恢复，后者继承其实现并提供回合、任务和用量视图 | 尾部半写须保留前一提交；中间损坏须拒绝自动修复；实际磁盘回归分别证明两种边界 |
| `SessionController.write` / `compress` | 复用当前会话取消代次、输入唤醒和保存上下文，替代系统内重复状态 | 普通写盘失败可等待重试，取消不能死锁；压缩候选保存失败不能采用；现有故障回归继续通过 |
| `UsagePanel` / `RunStatus` / `TextualOutputSink` | 分别由原生控件承载用量、运行状态及主线程展示；CLI/TUI 共用控制器 | 删除会损坏面板、Running/Queued 或跨线程流式展示；实际 Textual + API 验证和 ANSI/界面回归覆盖 |
| 工厂创建绑定与 `runtime.resources.bind_to_loop` | 以现有工厂注入模型、工具集、运行器；标准库跨循环投递用于拥有持久化状态的会话线程 | 工具／记忆不能再导入 core 具体实现；真实 Worker 和感知调用验证注入路径，依赖导入回归拒绝反向依赖 |

辅助用量沿用 `SessionController.usage` 的会话归属和既有写入重试，`RequestPolicy` 在输出校验前记录回执，`SessionFile._usage_updates` 供模型检查点与辅助调用共用去重逻辑。删除绑定会漏掉标题／压缩或把迟到用量写入新会话；跳过去重会使同一响应的保存重试重复累计，已有失败复现及真实重启累计值核验。辅助调用复用 `AgentRunner` 保留 SDK 中断响应，原同步线程包装和重复的压缩采用函数已删除；取消实测保留未知用量并保持原上下文。

新增 `ui` 是为去除 core 对终端和展示的依赖，新增 `sessions` 是为让渠道、工具和记忆共享输入身份、对话数据与事务，不把会话恢复混入模型编排。删除旧位置的实现而不保留空转发文件；WorkerOrchestrator 仍在 `tools/worker_tools.py`。`conversation_log_hint`／`conversation_log_extra` 经调用链检查未被任何日志或持久化消费者使用，随无作用的临时字典一并删除；实际会话日志、输入 ID、调用身份和 goal 迭代状态由已有入口记录，不重复另存。

记忆版本检查直接复用 `MemoryJob.bases`，索引完整性复用正式记录的正文指纹和现有索引身份；不新增独立版本或索引框架。`MemoryConflict` 区分已复现的版本／手工修改冲突与可重新生成的无效候选，避免用重新调用模型掩盖冲突。回归覆盖逆序候选、删除后旧候选及相同变更 ID 的幂等重试。真实 API 的数据库／投影故障恢复另核对持久化阶段、模型调用次数、正式版本和新会话画像；辅助检查本身不能替代这些真实证据。

渠道直接复用 `SessionController` 的输入登记和队列，AgentSystem 接收同一控制器，删除原独立队列状态。`QueuedTurn.prepare` 只负责按已登记顺序准备附件；绕过登记／代次检查会让慢附件晚于后续文本或进入清空后的会话。微信 SDK 的公开下载方法一次只处理首个附件，因此用标准库 `dataclasses.replace` 逐项调用；缺失文件及第二项失败均有回归。QQ 复用同一下载函数检查所有附件，删除静默丢弃分支。纯文本回答保持问答入口，不排在等待它的任务后面。非本人会话仍记录完成回合，个人记忆读取和生产保持权限限制；真实 API 与隔离回归分别核对计数及权限。

普通输入唤醒暂停保存也由 `SessionController.admit` 统一执行，删除 CLI 的专用分支；渠道无需复制同一逻辑。只读审查发现的实际缺陷是：存储恢复后的渠道新消息只排队，旧保存仍等待。辅助回归保留失败和修复结果；真实微信适配器在第一条实际模型响应后注入写盘失败，再接收第二条普通消息，两条回复按顺序完成、账本只有两次实际响应，证明恢复没有重复调用模型。真实机器人账号收发另行验收。

配置向导与校验共用 `config.schema.json`；类型、合法范围和必填关系是字段契约，不能夹带模型选择、凭据或运行默认值。`missing_startup_fields` 先解析预设，CLI／QQ／微信共用 `main`，渠道声明额外必填的 `bot` 区域。删除这一步会在构造机器人时因缺项退出；两个渠道已有失败复现和通过回归。数字字符串请求上限及 null 模型名覆盖保持旧语义。`Task.max_retries` 直接读取当前配置，旧检查点中的同名字段不再控制重试。

## 真实验收习惯

### 环境与范围

优先用户日常真实环境，不自行另造替代环境：

| 环境 | 已确认位置或入口 |
| --- | --- |
| 项目源码 | `E:\代码\Agent\.venv`，运行项目 `main.py` |
| 日常 pip | `D:\Software\miniconda\python.exe`，通过 CMD 的 `redlotus` 启动 |
| 打包程序 | 实际构建、解压的 PyInstaller onedir；onefile 是否纳入按当轮授权 |

工具不自动创建 venv；依赖安装明确实际解释器、目标和影响，不把依赖装到其他环境。新增组件、插件、参数变更或可能影响其他软件的依赖操作，遵循具体授权。

验收轮数、预算、期限和阶段以当轮批准方案为准，不自行扩充。原三环境全量目标仍是每环境 100 主会话＋20 跨会话、合计 360 轮；用户后来选择先完成定向验收，这不等于全量门槛已通过或已取消。

### 场景与证据

- 模拟从缺配置、安装、启动到对话、工具、退出和恢复的真实流程。源码通过不能替代 pip 或 EXE 通过，候选替换不能冒充版本升级。
- 重点覆盖不规范输入：无引号／相邻多文件、中文与空格路径、重复与缺失引用、20／21 文件边界、连续 5–6 条补充及最新纠正。
- 在慢附件、工具运行、流式回复、压缩和加载期间执行停止、清空、取消或切项目，核对实际输入 ID、请求边界、调用配对和文件内容。
- Ctrl+Enter 必须区分物理按键、终端协议注入和直接设置 urgent 参数的测试；新环境用检测结果，不按终端名称宣布支持。
- 开发题由 RedLotus 编写被测项目，测试者只提出需求、纠偏和独立验收，不代写实现或补丁。
- 真实模型、embedding、rerank、工具、产物与终端证据和本地辅助检查分别报告。人工夹具不能冒充真实感知生产。
- 自动压缩按实际阈值验证，不降低阈值或使用手动压缩充数。记忆校验新回合、overlap、ID、出处、更新、遗忘和跨项目边界。
- 缓存使用服务端 usage。主 Agent＋普通子 Agent 的总体目标 >90%，包含冷请求、恢复与压缩后请求；标题、感知、压缩单列，不预热或重复灌水凑数。
- 正常路径零个未预期 WARNING／ERROR；故障注入和预期拒绝单列。缺 usage、超时、未执行、外部阻塞和失败如实保留。
- 保存首次结果及批准次数内纠偏后的结果；不更换失败题面、篡改答案、放宽断言或修改日志等级获得通过。
- 记录 CPU、内存、Agent 线程、子进程、存储增长和积压。真实 API 延迟与框架等待分开定位；局部通过不能证明长期无资源问题。

已删除的测试源码和冻结题面不自行恢复或重建，不能把不存在的脚本写成可执行验收入口。需要续做完整题库时，沿用用户要求先确认题面与范围。

## 数据与清理

项目会话和日志属于项目 `.redlotus`，产物、引用与 runtime 属于项目 `WorkDatabase`。全部 LanceDB 记忆库可使用用户 `.redlotus`；不能把项目会话、下载、依赖或测试中间产物转移到 C、D 盘全局目录。
