# RedLotus 开发约定

本文规定开发偏好、修改边界及验收条件。组件行为以[项目设计](design.md)为依据，入口和数据归属见[项目总览](README.md)。

## 修改边界

- **禁止添加过度引导、裁剪、硬编码运行参数和隐藏默认值。** 每项修改对应明确需求，不自行增加配置、数量限制、依赖、框架或替代配置文件。
- 功能完整、正确和可读是前提。优先复用已有函数、合适的继承、标准库及第三方库原生能力，删除重复状态和无职责包装，不为假设问题增加扩展层或兜底分支。
- 保留用户已有工作区修改、删除和恢复的内容，不整体回滚，不借修复覆盖提示词或私人配置。重构保留可观察行为及副作用，不靠删功能、测试或断言达标。
- 已授权且必要的工作持续完成，不重复索取同一确认。实际设计分歧须说明差异、用途和影响；未获授权的功能扩展不并入修复。
- 修复先定位原因、保留首次失败，再做最小修改和原场景重测。结论不能超出证据范围，未知结果不能写成成功。
- 设计要求与实际实现的差异在任务交付中如实说明，不能把错误实现改写成新需求，也不能把待办或进度追加进设计稿。

## 配置与凭据

[三层逐字段读取规则](design.md#配置读取与编辑)是固定约定，未经用户明确要求不得改变来源、顺序或字段的合法空值语义。

参数范围以现有项目 `config.json` 为依据，保留 BFL 接入及其连接字段的明确例外。本地语音允许增加[语音配置与资源生命周期](design.md#配置与资源生命周期)规定的模型路径、资源参数及微信验证目标列表，使用该表公开默认值并沿用既有逐字段读取入口，不进入远程模型角色或首次连接向导；不能扩展为其他组件的隐藏回退，也不自动回写私人配置。`speech.tts_backend` 是受管理模型族枚举，默认 `mambo-onnx`；`speech.tts_package` 为优先使用的可选模型包目录，合法空值按选定模型族自动安装；非空值只选择指定包，更换包须改目录并重启。外部包自己的 `model.json` 是被动部署与完整哈希清单，不构成第四层用户配置，也不允许写入可执行代码、插件入口或额外运行参数。模型管理器的安装状态同样不构成第四层用户配置。不新增模型预设、命名网关、分层覆盖、额外别名、通用用户配置 schema 或运行参数填表。其他模型、采样、输出、RAG、路径及保留策略不搬入代码或隐藏模板。删除应用额外策略后使用库原生行为，不把库默认值抄成常量；显式业务入参仍须传递。

- 现有项目 `config.json`、项目 `.env` 和全局配置保持不变；只有用户明确授权的字段差异可以修改。修改前后核对字节及差异，不自动清洗无效旧字段或回写所有来源的合并结果。
- 禁止复制、备份、迁移、分发、上传或输出现有私人配置；禁止把配置、凭据和个人记忆放入模型输入、日志、夹具或被测 Agent 可读取的测试资料。
- 凭据仅用于相应服务认证。测试配置在明确的隔离临时目录人工构造，不从私人配置复制；只核对真实配置哈希，不输出私人字段清单或合并内容。
- 首次引导仅处理已有角色的模型选择与连接，不恢复非模型参数的启动依赖或缺项补填提示。模型及连接编辑继续保留凭据隐藏、Esc 取消不保存、文件锁和原子差异提交。
- 新增模型服务、外发材料、依赖环境或账号操作须在实际授权范围内。明确目标解释器、安装位置和影响，不修改无关全局依赖。

## 提示词与工具

- 应用维护的提示词使用英文并保留完整任务约束，放在提示词资源文件中；用户原文、引用和界面文案不强制翻译。未经允许不改写用户维护或恢复的正文，不把提示词放进配置或在 Python 中隐藏补写。
- 会话提示词快照、工具身份和上下文规则遵守[项目设计](design.md#提示词与压缩)。不通过重写 system、缩减输出配置、缩小证据窗口或截断原文获得压缩或缓存成绩。
- Agent 创建位置明确选择工具集合。英文函数 docstring 是唯一工具描述来源，签名、类型、返回值和实际行为一致，不通过外部 Markdown 改写描述或决定权限。
- Skills 渐进读取，执行经过共享检查入口；业务实现不能藏入 Skills 资源。保留工具层路径、进程、身份和审查边界，不引入系统 Hook、权限库或 IDE 插件绕过这些边界。
- 参数错误原样报告，不自动改写模型工具参数或事后修正产物。记忆改动聚焦正确写入、计数版本兼容和现有恢复流程。历史回合校正遵循[计数与存储契约](design.md#会话与数据存储)，不得重写已落库来源、调用模型或重跑工具；不增加无关维护命令或备份框架。

## 代码组织与精简

**代码简洁性是实现偏好，功能完整、正确和可读是前提。** 不以大函数、挤行、隐藏实现或删功能换取规模数字。

| 对象 | 硬性条件 |
| --- | --- |
| 应用模块 | 总数最多 10 个，包含本地语音 `TTS` 与独立桌宠 `pets`，职责对应[模块边界](design.md#架构与组件职责) |
| 模块文件 | 每模块递归最多 5 个 Python 文件，包含 `__init__.py` |
| 单文件规模 | 最多 500 有效代码行 |
| 应用规模统计 | 持续统计有效代码总量及物理增删；新增功能不受旧的全局净精简指标限制 |
| 自有测试 | 每组最多 5 个 Python 文件，每文件最多 500 有效代码行 |

有效行按 Python 逻辑语句换行统计，函数、类和装饰器计入；空行、注释及说明文档字符串不计，多行参数和续行合计一行。物理行数不设上限，只用于可读性与增删审查。此前净精简改造的“应用有效代码总量少于 10,373 行且删除行数大于新增行数”属于该专项的验收指标，不再作为新增语音等功能的全局门槛；不能靠删除说明、测试或既有功能凑数。`TTS` 的五文件职责固定在[语音模块设计](design.md#模块职责与接口)，接口接入不豁免其他模块的文件数和单文件行数限制。

第三方 Skills 资源不计入自有业务文件；自有工具、Skills 管理器及业务实现必须计入。测试和打包脚本单独核对，不能承载外移的应用实现。不得通过分号堆叠、嵌套目录、重复拆组、动态执行字符串或把业务代码放入资源规避限制。

新增或调整模块须说明唯一职责、必要性、替代与复用方案和依赖收益，不突破总数上限。每个函数的审查覆盖职责、调用方或注册入口、可复用方案、删除后受损的具体行为及验证依据。必要性以功能、正确性或资源回收损坏为依据，不要求整个程序崩溃，也不能人为制造依赖证明必要。

删除前核对直接调用、动态注册、SDK 回调、安装入口和既有接口，不能只凭文本搜索未命中。相似逻辑先检查共同职责，没有共同职责就不强行合并。异常处理须对应真实错误或可复现情形，在能恢复或准确报告的边界处理。

### 改造与审查

1. 改造前列明保留功能、故障证据、涉及职责、替代方案、预期有效行增删及必要的真实调用场景。
2. 实施中保留工具描述、权限、取消、资源回收和持久化语义；迁移须体现职责收益，不能仅更名或保留空代理。
3. 验收前核对模块、文件、有效行、净变化和异常处理依据。函数被调用、覆盖率或结构达标，均不能单独证明功能正确与职责必要。

## 测试与验收

### 环境和证据

验收范围、预算、轮数和服务目标按用户授权执行，不自行扩充。使用 Python 3.12 和明确指定的项目环境；安装制品回归使用授权的隔离目标，确认实际导入的是已安装 wheel。源码、pip、onedir 和 onefile 分别记录，不能互相替代。

回归应验证可观察行为，避免只复述实现。配置、网络故障和并发测试使用人工夹具；真实 API、embedding、rerank、模型输出、实际文件和终端操作单独验收，模拟结果不能冒充实际服务或账号收发。pytest 零收集视为失败，过期断言与跳过项说明原因，不通过删断言消除失败。

必要回归围绕现行契约重建，不恢复已删除的过时断言：运行目录组覆盖按需配置、优先级、工作区和 Skills 持久性；渠道组覆盖本人权限、独立会话、正文及附件、追问、排队、停止／清空和发送失败；计数组覆盖最终答复、暂停恢复、goal、历史关联、压缩与缺失证据、记忆游标和幂等校正。

应用源码实现必须同步更新 `scripts/check_structure.py`：检查本节规定的十模块上限、文件数和单文件有效代码行，保留应用总量及基线增删统计，不继续把旧的全局净精简指标作为新增功能门槛。CI 先运行结构检查，再运行源码回归、构建 wheel，并通过 `python scripts/verify_wheel.py dist` 在项目临时虚拟环境安装验证。测试及验证脚本单独统计，不得承载迁出的生产逻辑以绕过源码门槛。测试依赖复用调用解释器的第三方包，应用模块必须实际来自隔离环境安装的 wheel；导入来源不符立即失败。真实 QQ／微信账号、外部模型和物理终端验收单独记录，不以模拟回归代替。

只改文档时检查事实、链接、约束和修改范围；涉及运行行为时执行对应回归和制品检查。源码、测试、题库或候选变化后，不能用其他候选的结果替代当前验证。

### 行为覆盖

- 配置覆盖三层四种命中情况、嵌套逐字段读取、命中后不读下层、合法空值/零/布尔值/空列表、非法值报错、dotenv 格式和无宿主环境业务覆盖；核对已有连接不重复询问、Esc 取消不保存及配置字节不变。
- 启动覆盖仅模型与连接配置、可选组件按需读取及输入界面可用。日志覆盖超过大小阈值仍追加、保留期边界、缺失和停用、直属日志与子目录区分、`.log.1` 保留，以及清理先于输入开放。
- 引用覆盖中文、空格、引号、相邻路径、重复与缺失文件、配置上限及超过上限、多条补充和最新纠正；核对真实内容及不可变快照。
- 在附件准备、工具、子 Agent、流式回复、压缩和加载期间执行停止、取消、清空或切项目，核对输入身份、调用配对、实际文件和资源回收。
- 暂停覆盖模型流、工具、子 Agent、提问、待解析引用及任务完成边界；核对派发顺序、补充保留、连续点击、草稿和焦点、重载后仍暂停，以及恢复不重发已提交任务或重跑已完成工具。
- 传输故障覆盖首段前、部分正文后、工具完成后的断开及 SDK 包装原因，检查部分正文、思考、用量、错误和证据保留，没有自动重跑或成功误报。
- 终端键鼠验证覆盖 Enter、Ctrl+Enter、LF、修饰 CR、粘贴、空白、重复提交、按钮锁定和思考框折叠。PyCharm Terminal 与 Windows Terminal 的物理按键、协议注入和模拟事件分别记录，不按名称宣布支持，不修改用户终端设置。
- 文件操作覆盖原子替换失败、并发审查、外部修改、路径越界与随包 Skills 只读；任务覆盖依赖、失败不自动排队及显式恢复；记忆覆盖并发版本冲突、投影失败、索引补全和证据保留。
- 记录 CPU、内存、Agent 线程、子进程、存储增长和积压，区分服务延迟与框架等待。

### 桌宠开发与验收

源码开发安装 `pip install -e ".[dev,pets]"`；独立入口为 `python -m redlotus.pets.desktop charcoal`，也可用 `ivory`。CLI/TUI 通过 `/pets`、`/pets on [角色ID]`、`/pets off`、`/pets status`、`/pets list` 与 `/pets reload` 共用同一服务。`pets` 命名空间包只保留 `model.py`、`service.py`、`factory.py`、`desktop.py` 四个文件，不添加包初始化或第二个模块入口；每模块五文件与每文件 500 有效行上限保持不变。

内置桌宠直接维护在 `src/redlotus/static/pets`，只包含两个角色的简明动作 JSON/精灵图与来源说明；自定义资源放在 `~/.redlotus/pets`，不随包发布。按子目录发现角色，不再维护总清单；格式、同名覆盖和重载行为见[资源包制作说明](pet-resource-packs.md)。测试使用隔离资源目录，不修改 HOME/USERPROFILE 或真实用户素材。打包测试核对四文件模块、100 像素图集网格、动作引用、可选 Qt 依赖和分发边界。

自动测试覆盖五种动作、重复点击和拖动中断、异步并发启停、缺少 Qt、启动失败/超时、父管道 EOF 和资源完整性；缩放覆盖 50/100/300 物理像素、手柄锚点与动作隔离，气泡覆盖定位、滚动、关闭、悬停计时与 Unicode 截断。正文联动检查普通对话和 goal、语音独立、最终正文替换、取消/失败/迟到消息；人为阻塞管道和延迟就绪时，发布不阻塞主事件循环，内存有界，线程和任务在关闭后回收。

源码、安装 wheel、onedir、onefile 分别核对独立入口、角色选择、缩放恢复、气泡通信和退出回收；GUI 冒烟测试使用实际 Qt，并与真实终端、DPI、透明和跨屏验收分开记录。PyCharm Terminal 与 Windows Terminal 下的输入焦点、100%/125%/150%/200% 物理尺寸、多屏负坐标及屏幕拔除需实机核实；未测平台不声明已通过。详见[桌宠 v0.2 功能契约](superpowers/specs/2026-09-27-redlotus-desktop-pet-design.md#9-v02拖拽缩放与实时回复气泡)。

### 语音验收条件

语音功能以[本地语音设计](design.md#本地语音输入与输出)为契约。以下性能数字均为验收目标，不是已测成绩；模型作者的公开指标、压缩包大小、模拟音频或 SDK 成功响应不能替代本机与真实客户端证据。

| 范围 | 必须覆盖的场景与可观察结果 |
| --- | --- |
| 输入与 ASR | 普通话、英文、中英混合、数字、术语、静音、噪声、短音频、长音频、损坏文件；PCM/WAV/SILK 识别与不同采样率、声道转换；尾部样本不遗漏，中间结果不重复追加，最终结果只提交一次 |
| TUI 录音与转写 | 按下、松开、移出按钮后松开、短按、实时预览、连续录音、非空错字转写编辑后提交、录音打断播放、切换会话；实际采集开始即显示“录音中，请说话…”，不等 ASR 首字；ASR 就绪才允许采集，线程内非采集式设备预检查不得提前打开麦克风，预检查与实际打开须指向同一设备；麦克风 PCM 直接进 ASR，不写 WAV、音频证据或引用，用户编辑草稿是提交的权威正文；静音或最终空识别只显示“未识别到语音，请重试。”，不改草稿、不入附件、不提交；取消正常，旧回调不得覆盖新草稿或继续录音 |
| 麦克风选择与恢复 | 下拉框最多 44 个终端列，窄窗缩短，刷新按钮及语音回复开关紧随；默认跟随系统并显示实际设备。选定麦克风仅本次程序运行跨会话保留，重启恢复默认，不改系统或私人配置。刷新后按名称与后端唯一重匹配，缺失或歧义要求重选，不按枚举序号或隐式回退偷换；枚举、探测、打开、刷新均在线程内；录音和识别收尾期间不能切换。无设备、占用、权限错误简短提示，拔插后原进程刷新并重试；所有输入和输出流关闭后受控重初始化 PortAudio，且与新打开互斥 |
| 故障与日志 | 空识别由 `NoSpeechDetected` 子类单独表示，四个公共音频接口不变；真实故障界面只给温和简短提示，详细异常每次故障仅进项目语音文件日志一次，首次对话前也可落盘。启动准备及 `/voice prepare` 保留原始异常链，单个引擎失败立即报告，不等待另一引擎结束；诊断文件写入在线程中完成。每次实际采集在 `speech.log` 只有一条时长、电平、实际设备的简短统计，无原始音频；状态轮询同一故障只记一次，恢复后新故障可再记。自动测试断言真实应用日志通道及 TUI／终端没有红色堆栈，同时检查文件日志保留具体原因；不能通过替换 logger、降低日志级别或吞掉异常让断言通过 |
| 内存与资源 | 录音、识别、待播正文、输出编码均不写转写 WAV、播放 JSONL 或转换临时文件；正常结束、取消、异常均关闭采集、解析、推理及输出资源。渠道识别后移除消息中的原音频 `BinaryContent`，只保存一次转写；无音频引用快照、会话原音频或原始 base64 序列化，其他附件照常准备。QQ `Record` 使用 `base64://` 内存负载，微信上传内存字节，WAV `file_name` 仅是生成标签。本次安装尝试结束后，只自动清除来源及 SHA256 可确认的完整在线模型归档；复用已安装版本时也回收其遗留完整归档；合法未完成下载、离线用户归档与权重、归属不明的旧文件保留 |
| 正文与 TTS | 任意位置拆分的 delta、英文单词、小数、无标点长句、响应尾句、工具往返、跨 delta 的 goal 标记；默认曼波使用包内固定音色条件；显式选择 Kokoro 时保持纯英文 `af_maple`（sid 0）、中文及含中文句段 `zf_001`（sid 3）和英文数字读法，`3.14` 不拆段、`3.10` 的末尾零保留；显式模型包按其音色条件合成，不把品牌或 sid 写入公共业务；同一回复固定一个模型和音色条件，按正文顺序合成，不朗读思考或工具数据，最终完整展示不重复播报 |

| 生命周期 | 多会话并发、队列满、慢播放、慢发送、停止、暂停恢复、清空、切项目及退出；保留现有 FIFO、身份与回合统计，ASR/TTS 推理各自串行，原生调用结束前不释放推理名额；会话取消不停止共享启动准备，进程退出等待后台线程及原生操作结束，取消后无残留投递 |
| 安装与资源 | 明确使用 CPU wheel、固定 ONNX 资源和 `speech` extra 中的 `num2words==0.5.14`；纯文字请求不等待语音初始化，纯文字安装不要求语音依赖；启动立即独立准备、加载和预热两个引擎，TTS 中文与英文路径均预热完成前不假报就绪或缓存旧答复；全局复用及四种发行形态按[语音模型分发验收](#语音模型分发验收)核对 |

固定不少于 20 条真实发声的普通话、英文和中英混合语句，覆盖短句、长句、数字与术语；实际采集、识别、合成和播放均在内存中进行，不导出 WAV、MP3、原始录音副本或待播正文。报告只记录文字、版本、耗时及资源统计，检查调用期间实际文件写入，不能只凭结束后目录为空证明未落盘。明确由用户导入的专用音色资料按其持久资源规则管理，不属于日常音频测试产物。分别听评曼波的中文、英文与混合句段；显式选择 Kokoro 时另听评 `zf_001` 的中文和 `af_maple` 的纯英文，核对英文整数、小数、序数、百分比和末尾零的读法，不能只凭 ASR 回转写判断发音。固定双语文本通过 `/voice test` 的正式合成与播放路径在真实扬声器上确认可听、顺序和无重复；该命令不调用 LLM、不修改会话开关。另在真实 TUI 中用实际 Agent 正文触发语音，核对首声、连续播放及 `/voice off`、`/stop`、切换会话后的停止；独立模型脚本和注入式事件测试不替代真实 Agent 回复。

Markdown 回归逐项核对传入原生模型的最终文本：标题、强调、列表、引用、链接、图片、表格、行内代码、围栏／缩进代码块、HTML 注释与实体。完整输入、逐字符输入及每个二段拆分位置的正文结果须一致；覆盖未闭合语法、嵌套标记、数字、`C#`、`foo_bar` 和转义字符。确认代码块中的开关切换不朗读代码或补播旧片段，空正文不打开播放设备、不报错误，解析器与待播队列共用文本额度。界面及其他正文消费者保留 Markdown。真实 `/voice test`、经生产事件入口注入的 Markdown 听评、真实 TUI/Agent 结果分别记录。

外部 TTS 以[模型包与曼波制作约定](tts-model-package.md)为准。首个候选使用 MamboTTS v1.2.1 的现成曼波权重和配套参考资料，不要求用户录音或重新训练。制作端可在独立 GPU/PyTorch 环境完成核验、导出和打包；应用仍为无 PyTorch 的 CPU 推理环境，不引入其桌面客户端、完整 GPU 引擎或训练依赖。先听评未量化原始模型，再对比 ONNX 导出和量化效果，分别定位原模型、导出和分句播放造成的退化；架构或导出器不兼容时明确记录阻碍，不偷换音色或降低英文要求。

所有模型通过 `SpeechModel`、`ASRModel`、`TTSModel` 抽象方法接入，音色和合成请求使用类型化对象；工厂只选择应用已经支持的实现，模型包不能提供可执行入口。当前 sherpa-onnx 适配器不支持任意 ONNX 模型，新增流程须完成兼容性验证，不能仅修改清单冒充接入。模型实现处理前端与推理，服务协调后台准备、限流、取消和回收；业务流程不按品牌分支。外部包读取、SHA256 校验、加载、预热及占用锁操作使用 `asyncio.to_thread` 等既有线程协调路径；包自身只读，占用锁写在 `speech.model_dir/.locks`。取消必须等待实际后台操作退出。

曼波原生工作进程只从可信应用路径启动，通过绝对路径复用 sherpa 的 ONNX Runtime；握手核对协议、实际运行库路径和采样率，文本、消息头、音频及特征包均有长度或形状上限。四张图共用线程池和分配器，原生层通过有界分块返回自有 PCM，并以总字节数结束响应，不链接音频文件编解码库或重复重采样库；音色特征在制作端准备，运行时只读导入。取消或回调异常必须排空原生响应后再复用管道；核对分块长度、累计上限、完成总长与有限浮点样本，协议失步时回收进程。退出回收整个工作进程，禁止取消后启动替代实例来绕过未结束的调用。构建固定上游提交和受控补丁，不将模型包内文件作为执行入口。Windows 源码交付、sdist、wheel 和 PyInstaller 均携带同一已构建组件及许可证通知；Windows wheel 必须使用 x64 平台标签，缺组件的构建直接失败。非 Windows wheel 排除 Windows 程序且不宣称支持曼波；不支持的平台在下载前明确提示。PyInstaller 不额外复制第二份引擎，普通安装不执行训练或编译。子进程隔离不能表述为恶意模型安全沙箱，模型来源与完整性仍须核验。

应用接入编码前先完成最小 CPU 部署验证，核对完整推理链与 ONNX Runtime 复用可行性。分别列出应用制品、语音运行库、模型下载量及解压占用，记录新增二进制、重复引擎、完整依赖、冷启动检查/加载/预热与就绪耗时，以及 ASR 共存时的进程内存；包大小、安装文件大小与 RSS 不混用，不把 GPU 基准套用 CPU。优先复用已有引擎，不预设安装第二套运行库。现有约 1 GiB 常驻增量、首块 PCM P95 ≤1 秒和 RTF <1 目标不自动放宽；默认音源的选择不能代替指标验收，未通过不能宣称轻量或低延迟达标。

同一曼波音色使用至少 20 条中文、英文、中英混合、数字、术语及长句，并在内存中静默重复合成固定句十次；试听由操作者逐句触发，取消后停止后续试听，不自动连续重复播放。人工核对自然度、音色一致性、明显中断、漏读与重复。原始权重、ONNX 和量化候选使用同一语料对比，全部生成与播放只在内存中完成。原生适配和应用接入分别记录，验收 `/voice test` 和真实 Agent 正文，复验源码、已安装 wheel、onedir、onefile，并验证重复合成、取消与退出回收；官方演示、导出成功、ASR 回转写和旧版本测试不能替代真实试听或当前实现验收。覆盖 32 kHz 回调在原生推理结束前交付、连续重采样及唯一尾块，验证取消后的下一句不混入旧 PCM。性能报告保留并发负载和全部测量尝试；空闲间隔结果不得代替负载下结果，首块 PCM 不得当作首声。报告单独保存文字、版本、校验值、耗时和资源统计，不把成绩或历史经过追加到设计正文。

实机验收在 **PyCharm Terminal** 和 **Windows Terminal** 两种真实终端中分别以原命令 `uv run main.py` 启动当前 TUI。先用 `/voice test` 确认真实扬声器输出，再在 TUI 麦克风下拉框选择 **EDIFIER**，以真实麦克风连续录入中文、英文和数字，覆盖连续录音、松开按钮、移出后松开、编辑非空错字转写、静音、短按、拔插后刷新恢复；同时确认真实 Agent 正文语音输出仍可用。分别记录无输入设备、设备占用、权限受限和重新插入后重试的界面提示、实际选中设备及恢复；模型状态与录音设备提示分别核对，失败的输出设备测试不应妨碍 ASR 或文字交互。每次以最终转写判定识别结果，采样时长和电平仅用于定位问题，不能充当 ASR 成功证据；单次成功不能证明连续录音可靠。`uv run --no-sync python -B scripts/test_speech_input.py --seconds 15` 可在明确选择设备后，每次按 Enter 做一次 15 秒采集诊断，输入 q 退出；独立脚本、注入式 TUI 测试或旧版本 24 小时测试均不能替代当前 TUI 在这两个真实终端中的验收，未实测项目保持未验证。

基准固定 CPU 型号、核数、内存、运行系统、Python 与运行时版本、模型包及校验值、量化方式、推理线程、句段与音色选择、分段配置和测试语料。ASR 记录中文 CER、英文 WER 及中英混合样本结果；对照模型逐个加载，不以同驻多个模型的资源统计冒充双模型部署。TTS 核对中英文、数字和术语的可懂度、断句与片段衔接，不只统计生成成功。

| 指标 | 预热后的目标与计时口径 |
| --- | --- |
| ASR 首个中间结果 | P95 ≤800 ms；从首段有效语音样本进入解析接口到首个非空转写，不用纯静音样本缩短计时 |
| ASR 最终结果 | P95 ≤500 ms；从用户松开或音频输入结束到最终转写，包含尾部刷新 |
| TTS 首块 PCM | P95 ≤1 秒；从一个可合成文本段形成到其首块可消费 PCM，不含 LLM 首字等待 |
| TTS 持续合成 | 实时率 RTF <1，即合成耗时小于生成音频时长 |
| 常驻资源 | 两模型启用后的进程常驻内存增量目标约 1 GiB；同时记录峰值、空闲与负载值，CPU 方案不分配推理显存 |

分别记录冷启动检查、下载、校验、加载、预热、等待就绪和预热后的推理、排队、文本分句等待、解码、编码、播放及渠道上传耗时；展示用户实际首声延迟，不以推理局部指标替代端到端时间。实际模型下载与加载期间连续采样主事件循环调度延迟，并与空闲基线、普通文字界面响应比较；不能只以合成网络或假模型证明界面流畅。队列、内存正文缓冲和 PCM 窗口在慢消费者与突发请求下也必须有界，资源不足明确报告且不阻断文字回复。

本版以真实功能、发行形态和短时资源回收验收交付，不以 24 小时测试作为前置门槛。长期稳定性另行按授权验证：在同一固定配置下实际连续运行 24 小时，混合真实模型识别、合成、取消、失败及空闲恢复；比较相同负载下预热稳定期与末期的常驻内存，并记录峰值、线程数、句柄数、排队数、临时文件数量与大小。验收要求占用进入稳定区间，没有随请求次数持续增长的趋势；正式会话与引用增长单独归类，不能与临时泄漏混计。单次低内存、短时压测或把模拟时间推进 24 小时都不能证明长期稳定。

QQ、微信必须以真实测试账号核对客户端可见、可播放、时长与顺序。微信原生语音按目标账号验证，HTTP 成功、SDK 方法存在或上传成功不等同于播放成功；未验证时使用设计规定的附件模式。真实账号测试与 24 小时运行按实际授权执行，未执行的项目保持未验证，不得以模拟结果宣布通过。

### 语音模型分发验收

模型从[首次准备到更新清理](design.md#首次运行与模型目录)分别在源码、已安装 wheel、PyInstaller onedir 与 onefile 上验收。测试通过 `speech.model_dir` 指向隔离的 runtime 测试目录构造全新、已有、损坏及升级状态；显式包场景另设 `speech.tts_package` 指向只读测试包，核对缺失／损坏 `model.json`、每项资源 SHA256、链接与越界路径、切换目录后重启及 `model_dir/.locks` 占用锁。校验、加载和中英文预热线程内完成，失效包不得悄悄回退到内置清单。文字听评记录、延迟采样和长期运行统计放在隔离目录，日常音频不导出；明确导入的官方示例参考声音可作为持久音色资料。安装场景测试不使用或复制用户的真实全局模型，不修改 HOME/USERPROFILE，不以清空用户目录模拟首次运行；明确授权的真实播放可以只读复用已安装权重及必要占用锁。

| --- | --- |

| 并发与崩溃 | 多个进程同时首次启动、下载者退出、校验/解压/目录发布/状态提交期间崩溃；同资源单次下载、锁释放后可恢复、不读取半成品；目录和空间检查、锁等待、文件 I/O、哈希、解压、持久化、运行库导入、模型构造及预热都离开事件循环；工作线程通过 `call_soon_threadsafe` 更新内存快照，状态查询不访问磁盘；`threading.Event` 在分块、锁等待和文件工作中生效，取消异步任务不会提前释放仍在运行的原生操作 |

### 语音方案退役边界

自定义音色实现以[曼波制作约定](tts-model-package.md)为准；退役范围限定为 `ZipVoice/` 专属制作环境、下载权重、导出包、缓存与脚本，并将测试夹具中的旧模型假设改为相应的通用契约测试。先保留精简文字验收记录，包括自然度未通过的结论、产物身份和测量口径，不保留生成音频副本。

删除前检查实际解析路径、链接和进程占用，清理范围必须限定在确认归属该制作端的产物；不能递归跟随目录链接或顺带清理其他模型、用户原始音色资料及私人配置。旧配置指向已删除模型包时给出明确提示，不回写配置或静默切换声音。通用抽象类、模型工厂、被动包校验、内存音频链路及 Kokoro 清单与资源继续保留；旧环境的测试结果不能作为曼波验收证据。

### 长会话验收条件

使用冻结题库和同一最终候选，在源码、pip、onedir 各完成 100 主会话回合和 20 跨会话回合，共 360 回合；核对五个记忆窗口、第 19 回合后的恢复，以及各入口至少三次真实阈值自动压缩。onefile 的启动和核心流程独立验收。

记忆核对新回合、overlap、ID、出处、更新、遗忘及跨项目边界。自动压缩按实际配置阈值触发，不能降低阈值或以手动压缩充数。开发题由 RedLotus 编写被测项目，验收者提出需求、纠偏并独立检查，不代写实现或补丁。

缓存按服务端 usage 统计，主 Agent 与普通子 Agent 总体命中率必须 **大于 90%**，包含冷请求、恢复及压缩后请求；标题、感知和压缩单列。缺失 usage 保持未知，不按零消耗计算，不预热或重复灌水凑数。

正常路径不得出现未预期的 WARNING/ERROR，故障注入和预期拒绝单列。首次失败和授权范围内纠偏后的结果分别保留，不更换失败题面、篡改答案、放宽断言或改变日志等级获取通过。未执行和豁免项目保持未验证，局部通过不证明长期稳定。

## 数据与清理

数据遵守[项目归属](README.md#数据归属)，项目会话、下载、依赖缓存和测试中间资料不迁入无关全局目录。测试使用明确的隔离项目和记忆命名空间，不改 HOME/USERPROFILE 或用目录链接掩盖归属。

公共语音模型及其下载、版本与锁状态是明确的全局共享例外，统一归用户 `.redlotus/model` 或显式指定的模型根；明确导入的专用音色资料也按持久资源管理。该例外不包含日常录音、转写、临时播报内容或项目数据，也不扩大 Agent 的项目文件操作权限。模型管理器清理必须限定已登记且未占用的资源；项目缓存清理、应用升级和 pip 卸载不得顺带删除全局模型或用户原始音色资料。

用户自行添加的 `~/.redlotus/pets` 是跨项目共享的桌宠资源目录，只保存动作 JSON 与图集；应用只读使用，升级及项目缓存清理不删除这些资料。

onefile 包内资源由原生 bootloader 在启动环境选定的临时目录展开和清理，不改变业务数据归属，不在产品中硬编码机器路径。

临时项目、夹具、缓存、安装包和请求中间资料按授权清理。清理前核对解析后的绝对路径、所属范围和进程占用，不按目录名称猜测所有权，不删除正式会话、配置、引用、记忆或归属不明的产物。保留必要失败证据及脱敏结论，不把一次修复授权扩展为长期清理策略。

## 打包与交付

构建入口为 `scripts/pack.ps1`，支持 onedir 和 `-OneFile`，使用明确的已有解释器；构建目录、缓存和临时目录位于项目 runtime。制品须核对源码与资源一致性，排除私人配置、凭据、会话和运行数据。

`pets` extra 声明 `PySide6>=6.8,<7`，`all` 与 `build` 同样包含它，基础安装不依赖 Qt。桌宠静态资源仅从 `src/redlotus/static/pets` 的明确文件规则收集，wheel/sdist 与冻结制品共用这五个内置文件。PyInstaller 显式声明四个桌宠模块和 QtCore、QtGui、QtWidgets 的懒导入，依赖官方 hooks 收集所需原生库与平台插件，并收集 PySide6、PySide6_Essentials、shiboken6 的发行元数据及随附许可文件。`scripts/verify_wheel.py` 枚举 wheel/sdist，检查五个运行时资源、简明动作配置和 Qt extra；桌宠子入口无需模型配置或语音初始化。

语音分发默认不携带权重及模型配套资源。源码实现时同步核对 `pyproject.toml` 的 wheel 数据规则、`MANIFEST.in` 的 sdist 排除、`build.spec` 的显式资源/动态库收集及制品校验；`speech` extra 只声明运行所需依赖，包括纯 Python 的 `num2words==0.5.14`，不添加第二个 TTS 模型。EXE 包含所需语音运行库和小型模型清单，模型本身由首次运行下载至全局模型目录。不能仅凭 `.gitignore`、构建机未下载模型或制品体积判断已排除，必须枚举实际 wheel/sdist 与冻结制品内容；从 sdist 重建 wheel 也应满足相同边界。冻结程序使用标准 Playwright 浏览器资源收集，并保留随附许可证；资源收集方式的调整须独立完成实际界面验证后才能纳入发行。参见 [setuptools 分发文件规则](https://setuptools.pypa.io/en/latest/userguide/miscellaneous.html)、[PyInstaller spec 规则](https://pyinstaller.org/en/stable/spec-files.html)与 [Playwright 无界面浏览器说明](https://playwright.dev/python/docs/browsers)。

发布入口为 `scripts/publish.ps1 -Version <版本> -ArtifactDirectory <已验收目录>`。制品目录须提供指定版本唯一的 wheel、sdist 及 `SHA256SUMS.txt`；脚本核对项目版本、包内元数据、哈希及 PyPI 是否已存在该版本，仅上传已验收文件，不改版本、不重建、不清空制品目录。Token 从项目 `.env` 取得，仅在发布子进程环境中使用，结束后恢复原环境值。

CI 的 `.github/workflows/auxiliary-checks.yml` 配置 Windows、Linux、macOS 的构建、安装和隔离回归；工作流定义不代表各平台或真实服务已验收。发布须另有明确授权，公开发布后核对下载哈希、全新安装、启动和核心流程，失败不得覆盖旧制品或宣称完成。

交付说明实际修改、原因、验证及限制；提交、推送、合并、发布分别遵守授权范围。分支与 worktree 清理前核对独有改动、合并状态和占用，不覆盖其他工作。
