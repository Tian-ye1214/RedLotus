## 用户确认的约束

- 五个板块：core、tools、api、prompts、memory。
- 每板块递归不超过五个 Python 文件，每文件不超过 500 个有效代码行。
- 用户后续明确修改行数口径：空行、注释不计，多行参数/语句续行算一行；说明文档字符串不计，物理行数仍单独报告。不通过同一行塞入多条语句规避统计。
- 第三方 Skills 资源除外；不能把业务代码移出板块规避限制。
- 每 session 最多 16 个 Agent 线程；等待任务不得创建线程。
- session 只保存一个 model_messages.json，增量写入，恢复同一身份与计数。
- 进入项目先选择新建或恢复；旧会话删除，不迁移、不备份。
- 自动感知仅消费当前 session 每 20 个新增真实用户回合，附带 3 回合 overlap。
- 60 回合正常调度三次；主动记忆单独立即处理。
- 其余既有功能完整保留，包括引用、diff、审查、goal、CLI/TUI、Skills、RAG、QQ/微信。
- 模型及 RAG 参数不变；固定验收每次最多十分钟，不用超时结果宣称通过。

- `core/session.py`：输入队列与保存文件共同持有会话边界；取消准备阶段复用实际队列任务；统一状态锁与刷新、真实模型响应的用量投影。
- `core/console.py`：CLI/TUI 共享输入、引用补全和恢复选择，移除额外的准备状态副本。
- `core/presentation.py`：统一终端输出、流式预览、diff 和状态面板；移除无调用的旧流式入口及重复文本缓存。原 panel 模块归入该展示模块，合并后 487 个有效行。
- `core/system.py`：各入口共用用户停止及回执；清空/切换复用会话清理；节点及最终保存共用 checkpoint；goal 内迭代不重复扫描 Skills。
- `core/gateway.py`、`core/history.py`、`core/config.py`：分别收拢 SDK 工厂、上下文/用量和配置/基础资源，保持请求边界切换与原配置参数。
- `tools`：按执行、注册、引用、交互、工具集形成五个普通源码文件，工具与主 Agent 共用跨事件循环桥接。

没有增加运行时旧模块兼容壳、动态执行源码、或把应用实现搬到资源目录。
