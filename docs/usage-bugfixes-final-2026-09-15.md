## 新发现的问题及修复

| 问题 | 根因 | 修复与证据 |
|---|---|---|
| 模型没有返回正文，却把旧回复当成成功结果 | 已安装 Pydantic AI 2.0.0 的空响应恢复逻辑会向前寻找文本，可能取到工具执行前的说明，甚至上一轮答复。真实 CSV 任务文件已生成，但最后一次请求仅有思考内容 | 统一 Agent 工厂校验当前响应正文。空响应明确失败，保留工具回执，不自动重跑任务。原始真实历史恢复请求约 7.36 秒完成汇总，没有再次委派或执行命令；回归证明下一次继续仍保有旧工具结果，失败回合不会被写成成功证据 |
| 一次主动记忆纠正反复调用感知模型 | 感知的 `search_episodes` 只查情景，`search_memory` 原来只查全局，而 `read_memory` 又要求先从搜索结果得到 ID；当前项目的 requested 记录无法到达 | 感知的 `search_memory` 支持显式 project/global；已知 ID 可经授权检查直接读取，并保存更新前版本。四次真实纠正均各用 2 次感知请求，原先约 18 次的循环不再出现；始终更新同一个 ID |
| 仅查情景也能提交主动记忆 | 原先只检查搜索 scope，没有区分检索类型；显式请求省略 kind 时还会先按 episode 校验、之后转成 requested 保存 | 同时校验 scope 和最终保存的 kind。直接读取不替代去重搜索。先红后绿覆盖仅查 episode、kind 省略、跨项目 ID 拒绝，以及直接读取保存版本基线 |
| 验收脚本自己无期限等待 | 测试完成条件错误地要求总 events 为 20，实际自动窗为 20 个新增回合加 3 个 overlap | 改查 `window.new_turn_ids`。原窗口已完成、索引已写入、产物已验证，等待器被停止；不将这次停止标为应用正常退出通过。新增固定四回合入口和总期限，禁止不断扩展场景 |

没有更换模型、修改模型参数、RAG 参数或压缩阈值。此前获授权的 `execution.output_encodings` 保留；全局与开发配置的非 execution 部分分别与备份逐项相等。未增加 Windows 权限库、Hook 或账户隔离。
