## 修复内容

| 问题 | 原因与修改 | 验证结果 |
|---|---|---|
| 中文命令输出乱码 | 原来固定 UTF-8 并替换错误字节。配置增加 `execution.output_encodings: ["utf-8-sig", "locale"]`，UTF-16 BOM 优先；逐个严格解码，无法解码时保留转义原始字节并明确标记未验证 | 原生子进程 UTF-8、GBK、UTF-16 的中文 stdout/stderr 及退出码通过；真实 Worker 读取 Windows PowerShell 5 中文输出逐字一致，无替换字符 |
| 执行环境被推断为旧 PATH | 早期 `where python` 和目录不存在不能证明后一个进程使用何种解释器。统一 `CommandResult` 提供命令、cwd、启动时 Python on PATH、退出码、stdout/stderr；提示词要求实际解释器需当次 `sys.executable` 等证据 | 真实 Python 输出的解释器与工具选定的 E 盘项目环境一致；旧轨迹经真实感知重放后不再把 miniconda 推断保存为事实 |
| 局部操作完成被写成任务成功 | Worker 与感知混淆“回合结束”和“用户目标达成”。统一结构化状态及提示词，必要步骤失败不能以“完成诊断”改写执行目标 | 发布检查真实退出 9，Worker 整体返回 `failed`，同时保留前两项检查成功；真实记忆也为 `failed`，保留未决事项 |
| 解码失败仍被追踪为业务成功 | 只有自然语言解码提示，进程退出 0 仍可能被当作成功证据。增加 `output_decoded`，统一工具回执显式表示未验证；环境初始化也检查该状态 | 先红后绿的行为测试通过，原始错误字节与退出码仍保留 |
| 取消后的慢附件仍产生导入副作用 | 引用解析吞掉取消后，原来先保存引用，再检查输入是否属于当前会话。现在保存前再次验证登记归属 | 使用真实 PNG 二进制内容的迟到解析回归通过，旧会话不产生引用 manifest |
| 主 Agent 在明确委派任务前过度检查 | 环境尚未创建的说明未解释首次 Python 命令会自动准备环境。补充自动准备/复用说明与直接委派规则 | 首次多项任务因反复查看环境和框架源码被测试方停止，未交付 CSV；末次复测三次项目目录/文件检查后发起委派，但没有剩余额度运行 Worker。只确认委派已发生，端到端仍待验证 |
