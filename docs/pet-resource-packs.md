# 桌宠角色资源包

一个角色是一个目录，里面只有 `pet.json` 和透明背景的 `sprites.png`，无需 Python 代码或安装脚本。

## 放在哪里

内置角色随应用放在 `src/redlotus/static/pets/<角色ID>/`。自定义角色放在用户目录 `~/.redlotus/pets/<角色ID>/`；Windows 对应 `%USERPROFILE%\.redlotus\pets\<角色ID>\`。源码、pip、onedir 和 onefile 使用同一个用户目录，升级应用不会覆盖这里的素材。

目录名就是命令中的角色 ID，例如 `momo`。ID 不以点开头，不包含空白、斜杠、反斜杠或冒号。用户目录与内置角色同名时优先使用用户资源；损坏的覆盖包会报告错误，不悄悄恢复内置图像。移除整个覆盖目录后，重新加载会重新选中内置版本。应用只读取资源，不自动安装、复制或删除用户资源包。

## 制作精灵图

`sprites.png` 是图集，每格固定 **100×100 像素**，图片宽高必须是 100 的整数倍。帧从 0 开始，先从左到右，再从上到下编号。例如 400×400 图集的第一行是 0、1、2、3，第二行是 4、5、6、7。人物在各格中的脚底与画布位置应对齐，保留透明背景，避免动画跳动。

相同帧可在多个动作中复用，不要求填满整张图集。普通单张立绘不会自动生成新动作；可以让所有动作引用同一帧，得到可拖动、缩放的静态角色。只替换图片时须保持原帧位置及对应动作含义；改变排列时同步修改 JSON。

## 最小动作配置

一个只有一帧的角色可以使用：

```json
{
  "name": "我的桌宠",
  "actions": {
    "idle": [[0, 1000]],
    "look": [[0, 1000]],
    "happy": [[0, 1000]],
    "drag": [[0, 1000]],
    "sleep": [[0, 1000]]
  }
}
```

`name` 是非空显示名称，`actions` 必须包含上述五个非空序列。每项 `[帧编号, 毫秒数]` 的编号是从 0 开始的整数，时长是正整数。例如 `[[0, 1600], [1, 100], [0, 200]]` 表示普通姿势、短暂眨眼、恢复普通姿势。

| 动作 | 播放方式 |
| --- | --- |
| `idle` | 循环待机；30 秒无交互后进入睡眠 |
| `look` | 鼠标进入时播放，保持最后一帧 |
| `happy` | 点击后播放一次；连点合并，完成后按鼠标位置恢复 |
| `drag` | 拖动时循环，优先于其他动作 |
| `sleep` | 循环睡眠；鼠标互动立即唤醒 |

可选的 `enter` 与 `actions` 平级，给动作增加只播放一次的入场序列。例如 `"enter": {"sleep": [[11, 350]]}`：先播放第 11 帧 350 毫秒，再循环 `actions.sleep`。没有入场动作时省略整个字段。JSON 不接受其他字段，不包含图像路径、矩形坐标、动作优先级或鼠标事件配置。

## 加载与更新

```text
/pets list
/pets on momo
/pets reload
/pets off
```

`list` 刷新目录并显示角色 ID、名称、来源和无效资源原因；新增角色不需要登记总清单。输入补全只读取内存缓存，首次终端准备及 `list`、开启新角色和 `reload` 会刷新发现结果。

修改 `pet.json` 或 `sprites.png` 后执行 `/pets reload`。先校验资源，再重启当前桌宠子进程；缩放比例保留，位置按现有启动规则重新放置，动作和气泡重置。资源校验失败时旧桌宠继续运行，命令显示原因。通过校验后的进程启动失败则报告启动错误，并回收失败进程。关闭状态下 `reload` 只校验上次所选角色，不自动启动。

控制成功时不输出状态面板；用 `/pets status` 主动查询。新增／替换资源不会重启 RedLotus，不启用自动文件监视，也不影响 Agent 回复和语音。

源码还可用 `python -m redlotus.pets.desktop momo` 独立启动；该入口同样发现内置及用户目录。`--resource-dir` 是服务向子进程传递已解析绝对目录的入口，目录名必须与角色 ID 一致。
