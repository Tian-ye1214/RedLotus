# RedLotus 项目总览

> 审查基线：`ca98b811`；开发分支：`codex/lgtm-hardening`；状态更新于 2026-09-21。本轮按最新授权重新实施全部已列整改包，私人配置与提示词资源保留。面向项目开发者、维护者及后续 AI 协作者。

## 项目定位

RedLotus 是以终端为主要入口、围绕本地项目工作的个人 AI Agent。用户用自然语言提出需求，Agent 可以直接使用工具、委派子任务、调用 Skills，并通过项目记忆和长期记忆延续工作。

项目以用户打开的文件夹为工作边界。主要场景包括日常问答与资料整理、文案与计划、文件处理、编程和多步骤任务。QQ、微信是可选接入渠道，复用会话能力和身份权限。

它的重点是把对话落实为可检查的结果：实际文件、工具回执、任务状态、引用来源和可恢复的会话。工具层的路径与进程保护不等同于操作系统安全沙箱；模型输出仍需独立核验。

## 角色分工

| 角色 | 职责 |
| --- | --- |
| Coordinator | 接收用户请求、直接执行简单任务，或决定委派；汇总工具结果和用户补充 |
| Manager | 将复杂目标拆成带依赖的任务，协调执行并汇总；规划和最终汇报阶段的工具不同 |
| Worker | 执行有明确任务范围的子任务，返回结构化结果和证据 |
| 感知 Agent | 消费当前会话已封存的回合，生产项目记忆，必要时提炼长期记忆 |
| Compressor / Title | 分别压缩上下文和生成标题；不注册业务工具 |

子任务结果区分成功、失败、取消、待输入和未验证。任务清单的完成状态、Agent 是否运行、工具返回码及用户需求是否满足是不同概念，不能互相代替。

## 运行方式

| 方式 | 入口 | 本地配置查找基准 |
| --- | --- | --- |
| 源码 | 已有项目 Python 环境运行 `main.py` | 源码仓库根目录 |
| pip | 安装后执行 `redlotus` | 启动时的当前工作目录 |
| PyInstaller | 解压 onedir 后运行 `Agent.exe`；构建脚本也保留 onefile 选项 | EXE 所在目录，不是临时解压目录 |

配置逐字段按“本地 `src/redlotus/config.json` → 本地 `.env` → 用户 `~/.redlotus/config.json`”读取。仅检查对应基准目录，不向父目录搜索。安装包不携带实际配置或凭据，也不在启动时复制隐藏模板。运行策略全部读配置；`max_context_windows` 缺失或为 `null` 时使用既有 OpenRouter metadata，正整数才覆盖容量，不要求交互输入。首次配置须按模型、连接和凭据交互重新完善，取消不保存、确认只写修改；当前不能宣称全新用户流程或升级已通过。

源码与 pip 的 Python 工具使用启动程序的解释器；EXE 使用 PATH 中可找到的外部 Python。不会自动创建虚拟环境。浏览器、机器人和部分文档处理还需要各自的可选依赖。

## 数据归属

| 位置 | 内容 |
| --- | --- |
| 项目 `.redlotus` | 会话及角色恢复文件、轻量会话索引、感知进度、项目日志、用户维护的 `AGENT.md` |
| 项目 `WorkDatabase` | 任务产物、引用快照、runtime 依赖缓存、技能 overlay 和临时文件 |

项目记忆按 `project_id` 隔离，长期记忆可跨项目消费。正式数据位置由配置解析；不通过隐藏的 AppData 目录或短路径回退改变归属。

## LGTM 修复与验收入口

代码简洁性为开发与验收审批的最高优先级，优先复用函数、适用继承及标准库。允许按职责增加模块，最终原则上每模块最多 5 个 Python 文件、每文件最多 500 有效行；新增代码必须先提交具体变更包审批，逐行论证必要性、逐函数核对独立职责，不能靠挤行或搬文件达标。完整规则和反例见[开发与验收审批](development.md#开发与验收审批)。

以后每次功能测试、缺陷复测和发布验收，都必须像新用户一样按文档安装、配置和启动，从真实产品入口调用真实 API，检查实际结果及恢复。离线回归、mock 和打包检查只作辅助，不能单独作为测试完成或 LGTM 的依据；缺少真实运行条件的项目保持未验证。操作与报告要求见[真实验收习惯](development.md#真实验收习惯)。

真实 360 回合、自动压缩、各环境缓存、机器人账号、协议、浏览器与跨平台核心流程仍须逐项留证；pip 新版本应从发布索引实际安装后调用真实 API，当轮交付的 PyInstaller 制品也须直接启动完成真实流程。详见[设计与验收状态](design.md#本次验收边界)。

本轮最终辅助回归 **81 项通过**；源码、已安装 pip、实际 onedir／onefile 均完成真实 API 定向测试，包括 Worker、文件与命令、浏览器、手动压缩及用量；另有 Manager 依赖任务、问答停止、恢复和真实 TUI 审查竞争的证据。最终制品的资源完整性与凭据排除通过。新 pip 版本公开发布、360 回合、完整首次安装及跨平台门槛仍未完成；三平台 CI 尚未远端执行，已撤回实现的 108 项检查不计入本轮结果。

结构统计为 12 模块、50 个应用 Python 文件，每模块最多 5 个、每文件最多 499 有效行；13 个文件超过 500 物理行，不能把有效行检查称为物理行数达标。具体证据与剩余边界见[验收状态](design.md#验收状态与已知缺口)，测试维度见[场景与证据](development.md#场景与证据)。
