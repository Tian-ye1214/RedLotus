# RedLotus 项目总览

> 2026-09-22：已撤回此前 12 模块版本，正在基于 `ca98b811` 重新整改。最新版约束为原则上 6 模块、职责确有必要时最多 8 模块、每模块 5 个 Python 文件、每文件 500 有效行，物理行数不限；功能不得删减。下文能力表保留基线概况，新版真实证据与未完成门槛见[现行设计](design.md#验收状态与已知缺口)，不沿用旧发布通过记录。

## 项目定位

RedLotus 是以终端为主要入口、围绕本地项目工作的个人 AI Agent。用户用自然语言提出需求，Agent 可以直接使用工具、委派子任务、调用 Skills，并通过项目记忆和长期记忆延续工作。

项目以用户打开的文件夹为工作边界。主要场景包括日常问答与资料整理、文案与计划、文件处理、编程和多步骤任务。QQ、微信是可选接入渠道，复用会话能力和身份权限。

它的重点是把对话落实为可检查的结果：实际文件、工具回执、任务状态、引用来源和可恢复的会话。工具层的路径与进程保护不等同于操作系统安全沙箱；模型输出仍需独立核验。

## 角色分工

| 角色 | 职责 |
| --- | --- |
| Coordinator | 接收用户请求、直接执行简单任务，或决定委派；汇总工具结果和用户补充 |
| Manager | 将复杂目标拆成带依赖的任务，协调执行并汇总；规划和最终汇报阶段的工具不同 |
| Worker | 执行有明确任务范围的子任务，返回结构化结果和证据 |
| 感知 Agent | 消费当前会话已封存的回合，生产项目记忆，必要时提炼长期记忆 |
| Compressor / Title | 分别压缩上下文和生成标题；不注册业务工具 |

子任务结果区分成功、失败、取消、待输入和未验证。任务清单的完成状态、Agent 是否运行、工具返回码及用户需求是否满足是不同概念，不能互相代替。

## 运行方式

| 方式 | 入口 | 本地配置查找基准 |
| --- | --- | --- |
| 源码 | 已有项目 Python 环境运行 `main.py` | 源码仓库根目录 |
| pip | 安装后执行 `redlotus` | 启动时的当前工作目录 |
| PyInstaller | 解压 onedir 后运行 `Agent.exe`；构建脚本也保留 onefile 选项 | EXE 所在目录，不是临时解压目录 |

配置逐字段按“本地 `src/redlotus/config.json` → 本地 `.env` → 用户 `~/.redlotus/config.json`”读取。仅检查对应基准目录，不向父目录搜索。安装包不携带实际配置或凭据，也不在启动时复制隐藏模板。交互启动依据随包的公开字段契约收集必填缺项，确认后最小写回，取消不保存；字段契约不含配置默认值。非交互启动列出缺项。源码、日常 pip、onedir 的空配置提问与取消无写入已有真实入口证据；源码完整填写已在真实终端验证错误类型、角色复用和首轮 API，未写入凭据。pip／onedir 完整新人流程仍待最终候选验收。

源码与 pip 的 Python 工具使用启动程序的解释器；EXE 使用 PATH 中可找到的外部 Python。不会自动创建虚拟环境。浏览器、机器人和部分文档处理还需要各自的可选依赖。

## 数据归属

| 位置 | 内容 |
| --- | --- |
| 项目 `.redlotus` | 会话及角色恢复文件、轻量会话索引、感知进度、项目日志、用户维护的 `AGENT.md` |
| 项目 `WorkDatabase` | 任务产物、引用快照、runtime 依赖缓存、技能 overlay 和临时文件 |
| 用户 `~/.redlotus` | 全局配置、全部 LanceDB 记忆库、`MEMORY.md` 及必要全局日志 |

项目记忆按 `project_id` 隔离，长期记忆可跨项目消费。正式数据位置由配置解析；不通过隐藏的 AppData 目录或短路径回退改变归属。

## 版本与验收结论

基线源码的包版本仍为 `1.0.1`。仓库中的 1.0.1 发布记录与之后的 develop 改动不是同一制品；同版本候选 wheel 替换也不等于新版本公开发布。已发布制品应以 [PyPI](https://pypi.org/project/RedLotus/) 和 [GitHub Releases](https://github.com/Tian-ye1214/RedLotus/releases) 为准。

最新应用候选为 `f32c3217`，源码和隔离环境实际安装的 wheel 各 **210 项辅助回归通过**。PDF 链接遗漏已用真实 Word／Excel／PDF 请求复现并修复；同一旧会话再次引用原 PDF 也能取得链接，解析缓存升级并保持原有图片部件编号。新 wheel、onedir、onefile 的应用代码、资源及私人配置排除均已核对；实际 pip 文档请求与两个 EXE 的文档、Worker、浏览器、恢复流程通过，范围见设计记录。候选尚未公开发布。

用户批准把现有三个角色的压缩比例从 0.9 改为 0.8，仍按“（上下文容量－配置最大输出）×配置比例”计算，当前阈值为 504,628，最大输出保持 393,216；只修改明确批准的三个配置值。已安装 pip 的实际会话有 553,173 已知输入 Token，0.8 触发一次自动压缩，下一请求为 127,517，system 和旧账本保留。未增加分段压缩逻辑。

前版源码已完成 100 主回合＋20 跨会话、五个记忆窗口、五次恢复及四次自动压缩，核对题通过；Coordinator 缓存命中率 92.07%，没有普通子 Agent 长程调用。pip 也已完成 100 主回合＋20 跨会话，另有一轮 0.8 阈值验证；正式记忆的 100 组批次／代码及跨会话 20 题全部核对通过，五窗均已消费、提交和索引。第 100 窗最初因 `read_evidence` 超过重试上限失败，正式 CLI 对原窗口重试后成功，失败历史保留。该组 Coordinator 缓存命中率 96.95%，辅助角色单列，没有普通 Worker 长程调用；跨版本续跑不能算最终版本从头完成。onedir 已到第 80 回合，本窗压缩器自身仍被容量拒绝（926,744 输入＋131,072 最大输出超过 1,048,576），保留为未完成；降低连续请求阈值不能自动缩小已封存窗口的首次原文。实际 PyPI 1.0.0→本地 1.0.1 安装升级已有证据，旧配置／数据迁移仍待验收。各入口版本和剩余门槛见[验收记录](design.md#验收状态与已知缺口)。
