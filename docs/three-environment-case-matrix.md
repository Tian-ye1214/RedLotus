# 三环境全流程真实验收矩阵

本矩阵冻结 `develop@1df51729` 的发版前验收范围。它对应
[`scripts/final_acceptance_cases.json`](../scripts/final_acceptance_cases.json)：三种运行形态各执行同一套 120 个真实用户－助手回合，分别为一个 100 回合主会话与 20 个分散在短新会话中的回合。命令、快捷键、启动、安装和故障输入是独立动作，不能冒充用户－助手回合。

## 运行形态与隔离

| ID | 实际入口 | 首用／更新检查 | 数据边界 |
| --- | --- | --- | --- |
| `source_venv` | `E:\代码\Agent\.venv` 的源码入口 | 无全局配置的首启、填写／取消／错误配置、源码重启恢复 | E 盘本轮项目；显式测试配置目录；项目 `.redlotus` |
| `miniconda_pip` | `D:\Software\miniconda\python.exe`，日常 CMD 的 `redlotus` | 从公开 1.0.0 升级到候选包、重复安装、仓库外与中文空格目录启动 | E 盘本轮项目；显式测试配置目录；项目 `.redlotus` |
| `pyinstaller_onedir` | 本轮实际构建、解压后的 `Agent.exe` | 空白配置首启、onedir 替换、退出重启与 pip 产物兼容 | E 盘本轮项目；显式测试配置目录；项目 `.redlotus` |

三种环境均使用真实模型、embedding 与 rerank；不使用 FunctionModel、伪造 HTTP 响应、预填记忆或预写被测项目代码。测试驱动只创建题库声明的资料、随机校验码、起始空目录和独立核验脚本。它不能把校验码、参考实现或答案注入模型提示词。

每环境的配置流程遵循当前产品口径：本地 `src/redlotus/config.json` → 本地 `.env` → 指定用户目录的全局 `config.json`。首用缺少值时，先显示实际缺失字段和写入目标；取消不能保存半份配置或发起模型请求。测试凭据仅由运行器从日常已授权配置安全复制到隔离配置，不写入题库、报告、命令行或 Git。

## 回合分布与长会话断言

| 回合范围 | 主线 | 最低能力证据 |
| --- | --- | --- |
| `M001–M020` | 成都出行与个人工作安排 | 聊天、实时查询、资料引用、预算计算、主动项目记忆、六条加急、恢复后的第 20 回合感知 |
| `M021–M040` | 个人博客 | 文件与子 Agent、代码生成／执行、图片与文档引用、浏览器、首轮代码审查、第二个感知窗口 |
| `M041–M060` | HTML 打砖块游戏 | 需求迭代、触控／键盘、测试与实际试玩、长测试日志、diff 保留／撤销、第三个感知窗口 |
| `M061–M080` | FastAPI＋Vue 任务管理项目 | 项目脚手架、数据隔离、CRUD、筛选分页、指定环境、浏览器验收、长需求资料、第四个感知窗口 |
| `M081–M100` | 资料整理、复盘与交付 | PDF／Office／HTML／CSV、引用版本、长审计档案、总结、第五个感知窗口 |
| `S001–S020` | 短新会话与跨项目 | 主动记忆、纠正、遗忘、项目隔离、跨会话／跨形态消费、加载和统计 |

`M019` 后执行退出并选择恢复同一会话；`M020`、`M040`、`M060`、`M080`、`M100` 分别必须形成新增 20 回合窗口。窗口只消费当前 session 新增回合，附带已消费队尾的 3 回合作为 overlap。工具调用、重试、子 Agent 内部消息与同一外循环中的 Ctrl+Enter 补充均不增加计数。100 回合主会话应有恰好五个自动感知窗口；新建、加载和退出本身不产生收尾窗口。

长资料在 `M014`、`M034`、`M054`、`M074` 以真实引用进入会话。每个资料由运行器生成不少于 230,000 当前模型估算输入 token 的非重复、可追溯业务材料，包含后续问题必需的不同事实和随机校验码。资料不能用复制段落凑长度；每个资料须由至少两个后续回合引用其不同章节。实际自动压缩次数、触发请求、摘要和压缩后恢复核验都要保存；若 100 回合内不足三次，长周期验收失败，不能降低阈值、调用 `/compress` 充数或扩展回合数后改写结果。

## 已存在 CLI 命令映射

清单直接取自 `src/redlotus/core/console.py` 的 `COMMAND_HELP` 与 `src/redlotus/core/cli_commands.py` 的 dispatch。所有命令由题库的 `A009` 动作覆盖；它们不计入 120 回合。

| 会话与生命周期 | `/load`、`/clear`、`新任务`、`/cd <path>`、`/stop`、`/cancel <invocation_id>`、`/cancel agent <agent_id>`、`/exit`、`/quit`、`exit`、`quit`、`退出` | 选择器新建／恢复／取消、输入锁、恢复 ID、停止回执、项目隔离、退出释放 |
| 模型与配置 | `/agent`、`/agent <role> <preset-or-model>`、`/effort`、`/effort <role> <off-or-level>`、`/api`、`/api embedding` | 实际参数校验、保存目标与下一请求边界；配置动作只写隔离配置 |
| 记忆与上下文 | `/LTM show|clear|retry`、`/STM show|clear|retry`、`/compress` | 正确作用域、明确确认、重试、忙碌边界；手动压缩不占用户回合或自动感知窗口 |

## 真实验证规则

1. 每个案例保留首次交付与最多三次用户纠偏；纠偏只是原题的明确用户反馈，测试端不能给出实现片段、修复补丁或答案。
2. 产物由独立核验器读取文件、运行服务、检查 HTTP／浏览器页面、计算 fixture 中的随机数据并审阅工具回执。模型自述不构成通过。
3. 可选资源（浏览器、LibreOffice、图像服务、外部网络）缺失时记录为 `blocked_dependency`，附上实际检测结果；不能标记通过，也不能用模拟替代。
4. 每 20 主回合采样主进程与自有子进程 CPU、RSS、线程、子进程数、session 文件大小、项目磁盘增长和感知积压。线程上限为配置中的 16；停止／退出后只允许本轮明确持久化的会话与记忆保留。
5. 主 Agent 与普通子 Agent 的缓存按服务端实际 usage、包括冷请求与压缩后请求加权。每环境必须大于 90%；标题、压缩、感知单列。usage 缺失时标记未知，不以估算替代。
6. 测试完成且全部通过后，只删除本轮可验证归属的项目、隔离记忆命名空间、构建／下载／缓存和中间记录。真实用户配置、记忆、会话及归属不明资料不在清理范围。

## 首用、安装与更新动作

每环境在业务题库之前执行相同的动作序列：无配置启动、缺 `API_KEY`、缺模型名、空白值、错误类型、损坏 JSON、错误 KEY 和不可用模型。每项验证提示字段、来源和无请求副作用；随后通过 `/api` 或同一产品配置流程写入隔离配置并进行一次真实对话。之后验证帮助、补全、停止、退出重启、会话恢复与项目位置。

`miniconda_pip` 必须在日常 Miniconda 环境从公开 1.0.0 完成实际升级，确认 `redlotus` 命令和导入版本；重复安装不能覆盖隔离用户配置、会话、引用或记忆。`pyinstaller_onedir` 必须从实际构建产物启动并完成替换与重启；候选版本未变化时报告为制品替换而非虚构版本升级。所有构建、下载、解压、浏览器缓存、依赖与临时文件均位于 E 盘本轮目录。

跨运行形态恢复按顺序验证：Miniconda 从源码环境产生的测试 session 加载，onedir 从 Miniconda 产生的测试 session 加载。两次加载均不发模型请求，并用短会话 `S013–S014` 作为接收环境中的实际继续写入检查；源码环境的同名案例验证本形态恢复。这样三环境仍各自执行完整 120 回合，而跨形态兼容性不会额外伪造回合。
