# 项目存储与会话加载：LanceDB 收尾验收

基线为 `develop@d4a9bfb6179d3fa19608b51bd003c72eb067f452`，实现位于 `codex/project-storage-sqlite`。分支名称沿用现有工作树，当前后端为 LanceDB；正式数据未转换为 SQLite。

## 数据位置

| 位置 | 内容 |
|---|---|
| 项目 `.redlotus` | 单文件会话、轻量列表索引、感知进度、项目日志、用户维护的 `AGENT.md` |
| 项目 `WorkDatabase` | 产物、按内容哈希去重的引用快照、依赖、缓存、临时文件 |
| 用户 `.redlotus` | 全局配置、全部 LanceDB 记忆库、核心长期记忆及必要全局日志 |

项目记忆仍按 `project_id` 隔离。没有隐藏的数据库长路径回退；配置指定目录不可用时报告原因。已有记忆 ID 与库路径保留，不重新提炼或向量化。

## 修复范围

- 启动检查当前项目历史会话，提供新建、恢复、取消；TUI 常驻加载入口与 `/load` 共用控制器。
- 加载保持 session ID、提示词快照、引用、回合计数和感知进度，并显示历史内容；空项目首次输入前不创建会话正文。
- 项目切换、后台日志、图片引用恢复与空间清理使用所属项目上下文。
- 列表扫描只解析已提交进度，不修写会话正文；可恢复的尾部半写仍能选中，实际加载才提交修复，中间损坏单独标错。
- LanceDB 索引在锁外请求 embedding，写入前核对正文哈希、范围和有效状态，防止旧任务覆盖纠正或遗忘；索引失败独立重试。
- 临时目录缩短为项目 `{runtime}/tmp`，深路径 Python 使用同一文件的标准扩展路径拼写，依赖仍留在项目目录。
- 分发包保留已有工具依赖与资源白名单，不携带开发配置、凭据或测试记忆。

| 主要入口 | 单一职责 |
|---|---|
| `config._project_storage_path` | 按指定项目解析配置路径并拒绝项目外的会话、引用、运行目录 |
| `SessionFile.scan_info` | 扫描可重建的摘要索引，不改写聊天正文 |
| `session._write_with_cleanup` | 在所属项目内重试同一个已失败写入批次 |
| `AgentCliController.enter_current_workspace` | 锁定输入并处理新建、恢复、取消三种选择 |
| `RedLotusTui._show_loaded_conversation` | 将已恢复消息呈现到会话界面 |
| `MemoryStore._index_snapshot / _commit_index` | 分别领取待索引正文、核实版本后提交向量 |
| `execution._extended_path` | 保持实际文件不变，为 Windows 深路径 Python 启动提供标准路径拼写 |

## 已知限制

五板块已经保留，但 `core` 文件数及部分文件有效代码行数仍超过历史门槛。按既定有效行算法，27 个应用 Python 文件由 9,328 行变为 9,667 行，净增 339；其中 `cli_commands`、`console`、`tui` 新超过 500 行，其余越限在基线已存在。必要净增已获确认，结构超标并未通过。明细与配置段相等性见 `project-storage-source-audit.json`。

模型、RAG 服务、输出长度和压缩参数逐段保持基线原值；此次只调整项目存储与运行目录。测试通过只证明所列场景，不表示不存在其他缺陷。

SQLite 候选的性能失败与撤回原因见 `project-storage-performance.md`；此前试验的原始记录明确标为历史证据。
