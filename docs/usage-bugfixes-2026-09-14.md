## 尚未通过、后续最小修复方向

1. **记忆事实与完成状态仍有问题。** Worker 根据早期 `where python` 和环境尚不存在的查询，推断后续统计脚本使用了 miniconda；没有取得该次进程的解释器身份。感知把这项推断原样写为事实。实际上项目环境的 ready 标记早于统计脚本执行，框架在 Python 命令前也会准备并注入所选环境。不能将早期 PATH 查询等同于之后进程的执行证据。记录正文保留了 normal.ps1 的失败和未决项，但整体 status 为 success，未清晰区分“诊断调用结束”和“任务目标完成”。建议在现有命令结果中附带选定执行上下文，并统一 Worker/感知的状态与证据口径，再做真实重测；不按自然语言关键词机械改写记录。
2. **命令输出编码未修复。** Windows PowerShell 5 返回的中文错误为本机编码，当前 subprocess_runner 固定用 UTF-8 + replacement 解码，造成乱码。模型能够猜出常见错误不等于原始输出正确。后续应在 config.json 声明输出编码策略，以真实中文 stdout/stderr 验证，禁止静默替换。这与已修复的脚本文件输入编码是两个不同环节。
3. 慢附件期间 `/clear`、`/cd`、询问框迟到回调只有本批行为回归证据；未额外消耗真实模型请求覆盖全部组合。恢复第 20 回合使用调度夹具，真实记忆生产使用实际两回合退出窗口，二者不混称 20 回合真实验收。

本批不包含完整安装/打包、视频、长时间多次自动压缩或全量题库；未创建 build/dist。因上述限制与剩余问题，保持修复分支，不执行条件尚未满足的合并。
