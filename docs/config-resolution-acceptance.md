# 配置来源统一验收记录（2026-09-17）

基线：`develop@3a096a36`。实施分支：`codex/config-resolution`。

## 最终规则

每个字段按本地 `src/redlotus/config.json`、本地 `.env`、全局 `~/.redlotus/config.json` 的顺序取值。不搜索父目录，不使用全局 `.env` 作为额外来源，不从宿主环境变量取得模型凭据。文件损坏或类型错误不会被下一层隐藏。

| 入口 | 本地目录 | 修改目标 |
| --- | --- | --- |
| 源码 `main.py` | `main.py` 所在仓库 | 已有本地 JSON，否则全局 JSON |
| wheel 的 `redlotus` | 当前工作目录 | 同上 |
| PyInstaller EXE | EXE 所在目录 | 同上；不读取 `_MEIPASS` 中的配置 |

空白凭据和地址继续向低优先级查找；有效的 `false`、`0`、空列表和允许的 `null` 保留。`.env` 的嵌套键使用 `__`，不展开 `${宿主变量}`。命名网关的直接密钥和凭据引用也按来源排序。普通模型和命名网关的地址、密钥缺失时，在创建 HTTP 客户端前报出字段与来源。

读取返回独立深拷贝。`/config` 显示三层路径、文件是否存在和修改目标，密钥只显示是否填写。编辑只把实际变化写入目标 JSON；不把其他来源的凭据或模型参数复制进去。

## 函数职责

| 函数或对象 | 对应功能 |
| --- | --- |
| `local_config_root`、`config_sources`、`config_file` | 三种入口的读取基准、三层来源、修改目标 |
| `_parse_config`、`_validate_config` | JSON／`.env` 解析、结构和类型错误定位 |
| `_merge_config`、`ConfigValues` | 按字段合并、来源追踪、必填字段报错 |
| `settings`、`load_config` | 内容变化检测、缓存与独立配置副本 |
| `credential_value` | 命名网关直接值与凭据引用的优先级 |
| `_config_locks`、`_persist_changes`、`update_config` | 锁内修改并只持久化实际编辑 |
| `ModelTarget`、`create_model` | 角色配置快照与请求前连接配置校验 |
| `user_config_dir`、`user_data_dir`、`resolve_lancedb_dir` | `.redlotus` 默认归属及显式存储路径 |

## 仍需区分的范围

本轮不宣称长期记忆质量、60 回合感知、长期资源稳定性或所有第三方网关均已重新真实验收。旧代码结构超标继续保留；未为了配置调整扩大五板块重构。完整依赖独立安装超时也继续列为未通过。

入口实测使用非 TTY 管道，不等同于重新验证 Windows Terminal／PyCharm 的全部界面交互。EXE 的管道输入必须匹配其本地编码；跨编码发送仍可能出现 `UnicodeEncodeError`，这条原始失败保留，本轮没有扩大为 CLI 编码容错改造。
