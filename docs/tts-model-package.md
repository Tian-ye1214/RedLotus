# 本地 TTS 模型包与曼波制作约定

RedLotus 通过统一模型接口运行经过校验的本地音色包。Windows x64 默认选择曼波 TTS，Kokoro 作为显式可选后端保留；每次只加载选择的一套 TTS。默认选择不代表性能和发行验收自动通过，完成情况记录在独立验收报告中。界面、会话、分句与渠道不按模型品牌分支。

## 格式、运行库与轻量化边界

| 名称 | 职责 |
| --- | --- |
| ONNX | 描述模型计算结构、输入输出与权重的文件格式 |
| ONNX Runtime | 加载并执行兼容 ONNX 图的推理引擎 |
| sherpa-onnx | 基于引擎实现具体语音模型的文本/音频处理、模型调用与解码流程 |

依据：[ONNX](https://onnx.ai/)、[ONNX Runtime](https://onnxruntime.ai/docs/)、[sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/index.html)。导出格式与完整推理流程分别验证；多个图之间的调度、文本前端和音色条件不能仅靠文件扩展名推断。现有 sherpa-onnx 适配器不支持 GPT-SoVITS，不能将其 SoVITS 图当作普通 VITS 模型加载。上游[支持请求](https://github.com/k2-fsa/sherpa-onnx/issues/3694)不能代替可运行实现。

运行环境保持 CPU、无 PyTorch；独立制作环境可使用 GPU/PyTorch。曼波的受控原生组件 `redlotus_mambo.exe` 复用已安装 `sherpa_onnx/lib/onnxruntime.dll`，不安装第二份引擎或另一项目的客户端。当前构建要求 ONNX Runtime 1.28 API；父进程核验握手协议、采样率及实际加载 DLL 的绝对路径。组件不随模型包提供，模型包不能指定可执行文件或动态库。

原生组件在一个常驻子进程内顺序运行文本前端、GPT 编码与解码、SoVITS 声码器，四张图共享 CPU 线程池及内存分配器。父子只通过有界二进制管道传递文本和 PCM，不写临时音频。模型关闭时等待工作结束并回收子进程，连同原生全局词典一起释放；这是生命周期隔离，不是针对恶意原生模型的安全沙箱。应用退出导致输入管道关闭后，工作进程完成当前调用并退出。

应用制品、运行库安装文件、模型下载量、解压后权重、常驻内存和峰值分别统计。本机测量数值保存在独立验收记录，不作为设计常量。约 1 GiB 常驻增量、预热后首块 PCM P95 ≤1 秒、RTF <1 继续作为目标；未达标保持未验收，不自动放宽或替换默认音源。

## 现成曼波权重与独立制作

首个候选固定为 [MamboTTS v1.2.1](https://github.com/Tsukimisaka/MamboTTS/releases/tag/v1.2.1) 的曼波预设。其[发行归档](https://github.com/Tsukimisaka/MamboTTS/releases/expanded_assets/v1.2.1) `MamboTTS-v1.2.1-full.zip` 的 SHA256 为 `8c4e67356a34a347628deeb99680db16ab5daf8f3321cf6e4cd97ebbcdd8bbe3`；只提取需要的权重与参考资料，不运行客户端启动器或其引擎安装流程。

制作端核对该发行物中的 GPT、SoVITS 权重及配套参考音频、逐字文本。当前上游[接口约定](https://github.com/Tsukimisaka/MamboTTS/blob/main/engine_contract.py)列出 `manbo-e10.ckpt`、`manbo_e8_s168.pth` 和 `refer.wav`；下载后仍须以固定发行物及实际权重元数据确认架构和配对，不能从文件名推断训练条数、模型变体或导出兼容性。发布包有预设音色不等于其英文效果或 CPU 性能已经通过本项目验收。

制作流程为：下载与完整校验 → 架构和配套资源核验 → 原始未量化效果试听 → ONNX 导出 → 相同语料对比 → 最小 CPU 部署验证 → 被动模型包交付。使用现成权重不要求用户录音或重新训练；训练、微调与蒸馏属于独立制作能力，不是使用该预设的前提。

导出工具与原始权重版本必须匹配。[GPT-SoVITS ONNX 制作工具](https://github.com/GPT-SoVITS-Devel/GPT-SoVITS_minimal_inference)固定到 `6916eb2e9c227aeb28468ce6fa86ad5b17ead532`，[C++ 运行实现](https://github.com/GPT-SoVITS-Devel/GPT-SoVITS-cpp)固定到 `384a2f995c48ef1903373ac8814569a8925779ba`。受控补丁和原生入口在 `src/redlotus/TTS/native`，可复现的运行组件构建入口为 `scripts/build_native_speech.py`；应用安装、导入、首次准备和推理均不调用制作端。训练环境、导出脚本和构建缓存不属于运行交付。实际权重或文本前端不兼容时记录具体阻碍，不偷偷换声音、在应用中使用 PyTorch 或降低英文要求。

先建立未量化的原始权重与 ONNX 质量基线，再评估量化体积、速度及听感。机械感、句内停顿、断句、漏读、重复和英文退化必须分别检查；导出和量化不能仅以模型返回成功判定。原始模型、导出模型与应用分句/播放链路分别测量，避免将链路问题归因于训练数据量。

制作端的 `.pt`、`.pth`、`.ckpt`、优化器状态、训练脚本及依赖不进入 RedLotus 根环境、wheel 或 EXE。来源、资源与权重许可随交付记录，不把客户端代码许可自动当作全部音色资料的分发许可。应用首次运行只获取已经制作且验收过的部署资源，不执行转换、训练或模型包内脚本。

## 被动模型包与生命周期

部署包由一组 ONNX、必要文本处理资源、专用音色资料及 `model.json` 构成。文件角色随实际导出图固定，不用任意三个通用文件名假定整条流水线，也不扫描 ONNX 文件猜测用途。

| 内容 | 交付约定 |
| --- | --- |
| 模型图与必要外部权重数据 | 逐一记录角色、图接口、原生采样率及配套版本；仅保留最终运行路径需要的资源 |
| 文本前端 | 随包提供该实现需要的词典、分词或音素等被动资源，并验证中英文处理 |
| 专用音色资料 | 参考音频及对应文本，或已经验证的被动音色特征；与基础权重身份绑定 |
| `model.json` | 记录契约版本、后端兼容信息、基础模型与音色身份、来源版本，以及每项资源的非零字节数与完整 SHA256 |

现有 `schema: 1`、`runtime: "sherpa-onnx"` 清单只用于 Kokoro。曼波使用 `runtime: "mambo-onnx"`、`native_family: "gpt_sovits_v2"`、`cache_layout: "growing"`、`sample_rate: 32000`、`generation.mode: "features"`，固定以下角色，不能将旧的固定容量 KV 图混入：

| 角色 | 固定资源 | 契约 |
| --- | --- | --- |
| `gpt_encoder` | `gpt_encoder.onnx` | 音素、参考语义及 BERT 特征，输出首步分数与实际长度 KV |
| `gpt_step` | `gpt_step.onnx` | 当前 token、KV、文本及参考长度、步号，输出分数和增长后的 KV |
| `sovits` | `sovits.onnx` | 语义、文本音素、参考频谱和噪声尺度，输出 32 kHz PCM |
| `bert` | `bert.onnx` | 三组 tokenizer 输入，输出中文文本特征 |
| `config` | `config.json` | v2、32 kHz、最大上下文 2000、无 SV embedding |
| `voices` | `mambo.gsppkg` | 与该权重配对的音素、BERT、语义及频谱特征，不含日常音频 |
| `data_dir` | `frontend/` | 中英词典、tokenizer、分词和多音字资源；逐文件校验 |

独立制作端校验图接口、标准算子域与自包含权重，再生成逐文件大小和 SHA256。应用校验角色、版本、文件及特征包边界，再加载并预热；任一步不兼容都不能就绪。曼波部署包只量化 GPT 与 BERT，声码器保留 FP32；量化方案属于包身份，变更后重新验收。该契约不改变已有 Kokoro 清单的含义。

包内路径必须相对且限定在包目录中，所有必要文件均列入校验清单；目录不能用一个目录名代替内部文件校验。不允许路径穿越、符号链接、junction、未列出的原生文件、Python 模块入口、可执行脚本、自定义动态库或下载 URL。运行实现由应用随受控依赖提供，模型包只提供数据；哈希完整性不等于未知来源代码或权重自动可信。

发行包不携带权重。受应用管理的模型使用全局 `.redlotus/model`，通过后台下载、续传、SHA256 校验和原子安装流程管理；固定版本归档地址来自随应用交付的清单，不查询“最新版”或执行下载的脚本。`speech.tts_package` 未设置或为 `null` 时，`speech.tts_backend` 选择受管理的模型族，默认 `mambo-onnx`，显式 `sherpa-onnx` 选择 Kokoro。旧安装状态中激活的其他模型族不能覆盖当前选择；更新与回滚也只能在选定模型族内进行。平台或运行组件不支持时明确提示，不静默切换声音。

`speech.tts_package` 非空时优先选择该只读模型包，不下载另一个后端或接管外部资源。源码、安装后的 wheel、onedir 与 onefile 使用同一份清单、默认选择和全局目录，不要求填写制作目录，不修改私人配置或增加首次连接向导。发布前必须从实际公开下载地址在空模型目录中核对下载、校验、加载和预热；本地导入归档只能证明安装逻辑，不能代替首次下载验收。

外部包读取、校验、运行库导入、构造与中英文预热都在工作线程中完成，就绪前不积压旧回答。包保持只读，占用锁位于 `speech.model_dir/.locks`；状态查询只读内存快照，工作线程通过 `loop.call_soon_threadsafe` 发布状态。共享启动准备不被会话取消误停；退出等待真实后台工作和原生调用结束，不能提前释放模型名额。

外部包不由内置 `/voice update`、`rollback` 或 `clean` 接管。换包或切换受管理后端在重启后生效，不原地覆盖已加载资源；缺失、损坏或不支持的包给出明确提示，不悄悄回退或重写配置。显式选择 Kokoro 时，其自动下载、更新、回滚、双语音色与英文数字读法继续保留。

Windows 下文本前端路径兼容性单独验收。Kokoro 优先使用 ASCII 绝对路径或同一文件的短路径；必要时使用锚定当前目录的已核验相对路径。曼波子进程先从可信应用目录启动并按绝对路径加载运行库，再用 Windows Unicode API 锚定其只读模型目录，原生前端只读取固定相对资源。应用主进程工作目录始终不变，不映射驱动器、不运行时复制词典。

运行组件的重建入口为 `scripts/build_native_speech.py`，明确提供固定上游源码、构建目录、SDK、CMake、Rust 和 Cargo 缓存路径；脚本不安装全局工具，Cargo 离线构建，补丁不匹配即停止。源码交付与 sdist 保留已构建的 Windows x64 组件、受控源代码、所需 C++ 头文件、补丁及第三方通知，Windows wheel 使用 `py3-none-win_amd64` 标签；不能因组件遗漏而生成缺少曼波能力的 Windows 制品。PyInstaller 收集同一组件及通知，并复用 sherpa 自带引擎，不复制第二份 ONNX Runtime。非 Windows wheel 不携带 Windows 程序，也不宣称支持当前曼波后端。模型许可、第三方依赖许可和真实发行验收完成前不发布制品。

正常使用时启动应用，等待 TTS 就绪后输入 `/voice test`，通过正式合成与扬声器链路试听一次；无需制作环境或测试脚本。试听不调用大模型、不修改会话开关，程序返回成功仍须配合人工听感确认。

静默语料、取消、实际文件写入及资源测试的报告注明入口、版本和覆盖范围。冻结制品内的组件合成成功不代表完整 EXE 界面和播放通过。长期测试从模型就绪后计算实际工作时长，记录识别、合成、取消、资源趋势与运行空档；超过允许空档或被中断的运行保留失败证据，不自动重启覆盖。完成 24 小时仍须分析趋势，不能由进程仍存在推断通过。

## 抽象接口与内存边界

四个公共能力保留为类接口：`parse_input`、`recognize`、`synthesize`、`parse_output`。ASR 接收 16 kHz 单声道 float32 PCM，TTS 对外交付 24 kHz 单声道 float32 PCM；原生输出率不同须真实重采样，不能只修改采样率标签。

| 类型／方法 | 唯一职责 |
| --- | --- |
| `SpeechModel.load / warmup / close` | 加载、预热、释放一个模型实现，不下载或训练 |
| `ASRModel.create_session` | 创建独立识别状态，由会话接收 PCM、收尾和释放 |
| `VoiceProfile` | 描述音色身份、兼容基础模型与专用资料；不同声音使用数据对象 |
| `TTSModel.prepare_voice(profile)` | 检查兼容性并准备该后端需要的类型化音色条件 |
| `SynthesisRequest` | 携带纯文本与本轮固定的音色条件 |
| `TTSModel.generate(request, callback)` | 对有界文本执行前端与推理；返回 PCM，或分块回调后返回 `None`，已回调内容不重复消费 |
| `ModelFactory` | 按明确的能力和已支持实现构造模型，不执行下载、训练或渠道操作 |
| `SpeechService` | 共享实例、后台准备、线程调度、限流、取消与回收 |

使用枚举、dataclass 和抽象方法表达内部契约，裸字典只用于外部清单边界转换。`TTSBackend` 由工厂选择 `KokoroModel` 或 `MamboTTSModel`，分别使用 `SpeakerCondition` 和 `FeatureCondition`；服务不执行模型包脚本。方法职责正交，不使用独立函数转发壳或为每个声音创建子类。保持 `TTS` 最多五个 Python 文件、每文件最多 500 行有效代码；模型原生推理在随应用构建的 C++ 适配器中，制作与验收脚本不承担应用业务。

Markdown 转可朗读文本、共同正文订阅、分句与渠道规则不变；模型专属语言、数字和音色处理归模型实现。全进程只加载一套 ASR 与当前选定的一套 TTS，一个响应固定一个模型租约和音色条件，不同时常驻 Kokoro 与曼波。后台初始化各自去重，推理各自串行；原生调用未结束时不得释放名额或创建替代实例。

日常录音、合成 PCM、渠道编码与待播正文仅在内存消费；PCM 队列最多 2 秒，待播文字最多 4096 字符，渠道每次仅保留一个不超过 55 秒的编码片段。正文超限只结束本轮播报，文字回复继续。正常结束、取消、异常及切会话均释放缓冲、流、设备与任务，迟到结果不得继续投递。

明确导入的专用参考音频、文本或音色特征允许持久保存；运行时在线程中读取并在模型生命周期内只读复用，不生成副本。下载和原子安装暂存遵守既有恢复与清理规则，不与日常音频混同。曼波按语义 token 驱动声码器窗口，保留历史、前瞻和波形交叠，在句段完成前交付 PCM。协议 2 使用带长度的数据块和总字节数完成消息；每块与整段均有上限，取消后先排空响应再复用进程。父进程使用每次请求独立的有状态重采样器，将 32 kHz 转为 24 kHz 并只刷新一次尾部。该窗口合成不能称为逐帧生成；首块 PCM、实际首声、连续播放和内存峰值分别验收。

## 验收与接入顺序

制作与实现依次满足以下关卡；前一阶段通过不代表后续阶段完成。

1. **原始音色**：至少 20 条中文、英文、中英混合、数字、术语和长句，固定句在内存中静默重复合成十次，试听由操作者逐句触发，不自动连续重复播放。人工核对音色、自然度、连续性、句内停顿、漏读与重复，不以单个相似度或 ASR 回转写代替试听。
2. **导出一致性**：原始权重与未量化 ONNX 使用同一组语料和可比生成参数；另行比较量化候选。文本前端也须独立对齐：中文 BERT 输入保留制作端的 CLS/SEP，映射音素时移除两端特征，检查完整特征数值与长度，不能只核对 ONNX 图的输入形状。记录模型、文本前端和播放分段各自的影响，不能靠过度切碎文本满足时延数字。
3. **最小 CPU 部署**：在无 PyTorch 环境加载完整模型包，测量依赖、运行库与模型体积，记录冷启动各阶段、首块 PCM、实际首声、RTF、ASR 共存内存、线程及句柄。核验运行库复用并形成确定适配方案；未满足轻量目标时保留未验收状态，不改默认音源。
4. **应用链路**：通过生产 `/voice test` 和真实 Agent Markdown 回复试听，核对格式过滤、顺序、无重复、开关、停止、切换会话与异常。回归包缺失、篡改、路径越界、不支持的版本及取消；默认曼波、显式选择 Kokoro 和 X-ASR 分别验收。
5. **分发与稳定性**：源码、已安装 wheel、onedir、onefile 分别真实推理播放，检查制品不包含权重和制作依赖；验证重复合成、取消和退出回收。24 小时资源测试作为独立的长期验证，不阻塞本版功能交付；未完成时不声明长稳通过。QQ、微信仍需真实账号独立验收。

测试音频在内存生成、消费和试听，不写 WAV、MP3 或待播文件；检查实际写入行为，不能只检查结束后目录为空。报告仅保存文字、版本、校验值、耗时、资源趋势和未执行项目。原始音色、导出及部署分别记录结果，旧环境记录不能作为新实现证据；导出成功只代表制作阶段完成，真实试听与轻量部署均通过后才作为可用音色交付。

退役产物范围与删除安全边界见[开发约定](development.md#语音方案退役边界)，其他真实设备、渠道及分发要求见[语音验收条件](development.md#语音验收条件)。
